# Virtumetry Backend

Fastify API + Postgres-backed job queue for Virtumetry. Forked from an earlier
backend and stripped to the scan upload path; Echo-3 reconstruction lands in a
later phase (mock provider only for now).

## Stack

- **TypeScript** (strict, NodeNext), Node 24, ESM.
- **Fastify 5** + **zod** for HTTP and validation.
- **Drizzle ORM** over Postgres (`pg` driver); migrations generated by **drizzle-kit**.
- **Vitest** for tests.
- Storage behind an S3-compatible driver: local disk for dev, Cloudflare R2 in production.

## Setup

Run every npm command from inside `backend/` (it holds the only lockfile).

```bash
cd backend
npm ci
cp .env.example .env      # fill in DATABASE_URL, MIGRATE_DATABASE_URL, DEV_AUTH_TOKEN
npx tsx --import dotenv/config src/migrate.ts   # apply migrations (direct host)
npm run dev               # http://localhost:8080/healthz
```

## Scripts

| Script | What it does |
|---|---|
| `dev` | `tsx watch` the server, loading `.env` via dotenv |
| `worker` | run the worker loop (`src/worker.ts`) |
| `build` | `tsc` to `dist/` |
| `start` | run `dist/${SERVICE_ENTRY:-server}.js` |
| `typecheck` | `tsc --noEmit` |
| `test` | `vitest run` (Postgres integration suites skip without `TEST_DATABASE_URL`) |
| `db:generate` | drizzle-kit: SQL migration from `src/db/schema.ts` (no DB needed) |
| `db:migrate:prod` | `node dist/migrate.js`: drizzle-orm migrator, advisory-locked; the release step |

Never use `drizzle-kit push`.

## API surface

- `GET /healthz`
- `POST /v1/worlds` (idempotent on `client_request_id`, daily scan quota)
- `POST /v1/worlds/:id/uploads:refresh` (re-presign frame upload URLs)
- `POST /v1/worlds/:id/frames:done`: flips `uploading` to `uploaded`, enqueues nothing yet
- `GET /v1/worlds`, `GET /v1/worlds/:id`, `DELETE /v1/worlds/:id`
- `GET /v1/me/quota`, `POST /v1/devices`, `DELETE /v1/account`

## Migrations

Edit `src/db/schema.ts`, then `npm run db:generate` writes SQL + snapshot into
`drizzle/`. History starts at `0000_init.sql`.

`src/migrate.ts` applies committed SQL with drizzle-orm's migrator under a
Postgres advisory lock on a dedicated `pg.Client`. It connects with
`MIGRATE_DATABASE_URL` and must use the **direct** (non-pooler) Neon host,
because the session-scoped lock does not survive a transaction pooler. The
bookkeeping table is `drizzle.__drizzle_migrations`.

It is a release step (Railway pre-deploy on the `api` service only), never run
at server/worker boot.

## Rate limiting

`@fastify/rate-limit`, keyed per user when authenticated, per IP otherwise.
`POST /v1/worlds` has its own small `create:<user>` bucket
(`RATE_LIMIT_CREATE_MAX`); failed authentications are capped per IP
(`AUTH_FAIL_MAX`). Window: `RATE_LIMIT_WINDOW_MS`.

## Dev storage (`STORAGE_DRIVER=local`)

Presigned URLs point at `/dev-storage/<key>` routes (registered only for the
local driver) that read and write `LOCAL_STORAGE_DIR`, path-traversal-checked.
`STORAGE_DRIVER=s3` signs real R2/S3 URLs instead.

## Job queue and worker

Jobs live in Postgres and are claimed with `FOR UPDATE SKIP LOCKED` leases. The
only job kind today is `purge`; reconstruction kinds arrive with the Echo-3
provider.
