# Phase 6.1 Design Critique Log (impeccable)

Each round: what impeccable flagged, what was decided or fixed. Round 0 runs before the UI-SPEC and is binding input for it. Later rounds run after execution, screen by screen, until the result reads as a premium product.

## Round 0: pre-spec decisions (2026-11-25)

Context: `PRODUCT.md` (register: product), owner palette, `06.1-CONTEXT.md`.

### Theme (scene sentence)

"The owner stands in a half-lit living room in the evening, phone held up at chest height, walking slowly while the camera feed fills the screen; later they show the finished room to someone on the couch." Camera feeds and splat worlds read best against near-black chrome, and OLED black stays calm in dim rooms. **Dark is earned, not a default.** Keep `#060a0a` as canvas; never pure `#000`/`#fff`.

### Colour strategy: Restrained, with two Committed moments

- Product register → **Restrained**: tinted near-black neutrals, mint `primary #a2cccb` reserved for the single primary action per screen, focus, current selection and success-adjacent progress. Not for decoration, not for inactive states.
- **Committed moments** (earned): onboarding pages and the first-run empty Library may carry a large indigo `secondary #3e4a71` → `accent #6b6cae` field behind the illustration. The rest of the app stays quiet.
- `accent #6b6cae` on `#060a0a` is about 4:1: **never for body text**. Use it for large type, icons, progress fills, coach-mark surfaces (with light text on top checked at AA).
- Neutrals: derive surfaces in OKLCH by stepping lightness up from the background with a slight blue-teal tint (hue between primary and secondary, chroma 0.01–0.02). Two surface layers max (base, raised) plus one overlay/scrim. No nested cards.
- Status colours (success/warning/danger) re-tuned to sit in the palette (desaturated, cool-leaning) and each paired with an icon + text, never colour alone.

### Typography (font selection procedure)

1. Brand-voice words: **exact, calm, spatial** (physical objects: a surveyor's instrument label, an architect's drawing title block, museum wayfinding).
2. Reflex picks: Space Grotesk, Inter, Sora. Space Grotesk and Inter are on the reflex-reject list → rejected. Sora is a geometric "modern" reflex → rejected.
3. Chosen system (all loadable in Expo Go via `@expo-google-fonts/*` + `expo-font`):
   - **Display / headings: Schibsted Grotesk** (600, 700). A sturdy, slightly condensed news grotesk with real character at large sizes; reads like signage, not like a SaaS template. Used only for screen titles, section heads, onboarding headlines, empty-state headlines, the world title in the viewer.
   - **Body / UI: system (SF Pro on iOS, system-ui on web).** Product register: buttons, labels, list rows, inputs, toasts stay native for legibility, Dynamic Type behaviour and zero layout risk. No display face in buttons or labels.
   - **Readouts: Martian Mono** (400, 500), tabular by nature. Only for measured numbers and machine-like values: measured distance, frame counts, credits and cost, coverage percent, upload progress, link view counts, small uppercase eyebrows. This is the "instrument" voice and the brand's most recognisable detail.
4. Cross-check: not a serif "for premium", not a geometric "for modern", not the editorial lane. Passes.

Scale (fixed, product register, ≥1.2 between steps; sizes in pt):

| Token | Face | Size / line | Weight | Tracking | Use |
|---|---|---|---|---|---|
| display | Schibsted Grotesk | 34 / 40 | 700 | -0.5 | onboarding headline, first-run hero |
| title | Schibsted Grotesk | 28 / 34 | 700 | -0.3 | screen titles |
| heading | Schibsted Grotesk | 20 / 26 | 600 | -0.1 | section heads, sheet titles, world title |
| body | System | 17 / 24 | 400 | 0.1 | body copy (light on dark: +leading, +tracking) |
| bodyStrong | System | 17 / 24 | 600 | 0.1 | emphasised body, button labels |
| label | System | 15 / 20 | 500 | 0.1 | row secondary, input labels, toasts |
| caption | System | 13 / 18 | 400 | 0.2 | metadata, helper text (min size; never below 13) |
| readout | Martian Mono | 15 / 20 | 500 | 0 | numbers and values |
| readoutLarge | Martian Mono | 28 / 32 | 500 | -0.5 | measured distance, quote total |
| eyebrow | Martian Mono | 11 / 14 | 500 | +1.2 (uppercase) | small section eyebrows, step counters |

Dynamic Type: body/label/caption scale with `maxFontSizeMultiplier` 1.6; display/title/heading cap at 1.3; readouts cap at 1.4; eyebrow caps at 1.2. Light-on-dark compensation: body leading +0.1 over the default, tracking +0.1.

Viewer DOM component and web share page: load the same two families via CSS `@font-face` from the bundled font files (or Google Fonts CSS on web), `font-display: swap`, falling back to `system-ui` / `ui-monospace`.

### Layout and components

- Avoid card soup: Library rows are full-bleed rows with a leading thumbnail and dividers, not a grid of identical cards. Settings uses grouped rows (iOS inset-grouped pattern), not cards in cards.
- Vary spacing for rhythm (8-pt base with 4 for fine detail; generous 32/48 between sections, 12/16 inside groups).
- **Banned here:** side-stripe callouts (the budget banner must not be a coloured left-border box: use a tinted full surface with a leading icon), gradient text, decorative glass (allowed only where iOS itself provides it: native tab bar), hero-metric layouts (cost quote shows one readout with plain context, not a stat dashboard), modals as first thought (sheets already exist for share/retry; keep them, no new modals).
- Skeletons, not spinners, for content loading. A spinner is allowed only inside a button that is working.
- Empty states teach: first-run empty Library explains the three steps and offers the one primary action ("Scan a room").

### Motion

- 150–250 ms for state changes; ease-out quart/quint/expo curves; **no bounce, no spring overshoot, no elastic**. Press feedback: scale 0.97 + opacity in 120 ms.
- Motion only for state: press, appear/disappear, progress, mode change, toast in/out, coach-mark reveal, onboarding page change. No orchestrated page-load choreography.
- One crafted moment allowed: the first time a world becomes ready (Library row transitions into "Ready" with a short mint pulse on the status, plus a success haptic). Reduce Motion: instant.

### Copy

- **No em dashes or `--` in any user-facing string.** Existing strings that use them get rewritten (commas, colons, periods).
- No headings restated by intros, no exclamation marks for routine success, numbers as readouts ("~918 credits · about $9.18").
- Toasts: one short sentence, verb first for actions ("Link copied", "Name saved", "Couldn't discard. Try again.").

### Icons

- SF Symbols (expo-symbols) in one weight (medium) and two sizes (20, 24); hierarchical rendering for status icons. Same glyph for the same concept everywhere (e.g. `cube.transparent` for worlds, `ruler` for measure, `figure.walk` for walk, `map` for floor plan, `link` for share).
- Web share page and viewer DOM: inline SVG equivalents drawn on the same 24-grid with 1.75 stroke so the two platforms feel the same.

### Onboarding and coach marks

- Onboarding is the one Committed-colour surface: 4 pages (Walk the room → Check before you pay → We build it → Walk, measure, share), each a vector illustration + one headline (display) + one sentence (body). Skip is always visible; final CTA is "Scan your first room" only if the Library is empty, otherwise "Go to library". No fake progress, no account upsell.
- Coach marks: small anchored callouts on raised surface with an accent outline, one sentence + "Got it". Never stack two at once.

### Toasts

- Top, below the safe area, full-width minus 16 margins, raised surface, leading status icon in status colour, label text in `text`. No coloured full backgrounds (keeps contrast and calm). Errors stay until 6 s or dismiss; success/info 3 s.

### Risks flagged for the UI-SPEC to resolve

1. Contrast of muted text and of `accent` uses: compute every pair and publish the table.
2. Martian Mono is wide: check that quote and upload readouts fit at Dynamic Type caps on a 393-pt-wide screen.
3. Fonts must not block first render: hold the splash until fonts load (`useFonts`), with a timeout fallback to system.
4. Viewer DOM fonts: confirm the DOM component can reference bundled font assets; else fall back to system for in-viewer chrome (acceptable).

## Round 1: post-execution critique (2026-11-26)

Method: impeccable critique. Assessment A = independent design-director review of the implemented source + rendered icon (sub-agent, isolated). Assessment B = `npx impeccable@4.11.1 --json src/app src/components src/viewer` → **0 findings** (the detector targets web CSS patterns; weak evidence for RN StyleSheet code, so A carries the round).

**Score: 28/40 (Good).** Absolute bans all clear (no gradient text, side stripes, decorative glass, hero metrics, em dashes). Cognitive load: 3 failures (moderate), all on the capture HUD + money units.

**AI-slop verdict: competent, partially templated.** The core flow reads like careful native iOS; the two "crafted moments" (onboarding, empty Library) read as the stock template: diagonal indigo→violet gradient card + thin line art + dots + duplicated "1 OF 4" eyebrow. Mono eyebrows spent on non-readouts dilute the "instrument" voice. Mint leaks into decorative art. The room is never the hero (64-pt thumbnails, cube icons for local scans that have frames on disk).

|---|---|---|---|
