# Phase 06.1 Plan 05: Core UI Primitives Summary

This plan adds 12 token-only primitives in `src/components/ui/`. Buttons share one press feel: scale 0.97 over 120 ms outQuart, with only the fill change when Reduce Motion is on. Primary presses fire a light haptic, SegmentedControl changes fire a selection haptic, and every control has a tested a11y contract.

## Notes for downstream plans

- `Icon` takes concept names (`ready`, `warning`, `offline`…), not SF names. `selected` switches library/settings to the `.fill` SF variant.
- `Button` has `testID="button-busy"` on its spinner. Its accessible name stays the same while busy, which the capture-quote and share-sheet tests rely on.
- `SegmentedControl optionRole="button"` with `accessibilityLabelFor={(o) => \`${o.label} scenario\`}` keeps the scan-screen contract.
- `TextField` accepts `ref` (React 19 prop) and forwards all TextInput props. It never logs values (T-06.1-10).
- `Screen` scrolls when `scroll` or `refresh` is set. `refresh` adds a RefreshControl tinted with primary.

## Deviations from Plan

- **[Rule 3 - Blocking] RNTL 14 has no `UNSAFE_getByType`.** Tests mock `expo-symbols` with a `jest.fn` to read the props passed to `SymbolView` (the iOS build reduces `name` to its ios string). Button's spinner gets a testID.
- **Radiogroup not asserted in tests:** RNTL only matches roles on `accessible` elements, and making the group container accessible would hide its radios on iOS. The container keeps `accessibilityRole="radiogroup"`. The tests assert the radio items.

Otherwise the plan was executed as written.
