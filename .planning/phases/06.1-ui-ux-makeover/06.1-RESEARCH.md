# Phase 06.1: UI/UX Makeover - Research

**Researched:** 2026-11-26
**Domain:** Expo SDK 58 (Expo Go) design system, motion, haptics, fonts, icons, onboarding/coach marks, toasts, jest test infrastructure
**Confidence:** HIGH for jest/tooling facts (verified empirically in this repo), MEDIUM for on-device iOS behaviour (Expo Go / WKWebView / native modals)

## Summary

The UI-SPEC is the approved WHAT. This research covers the HOW: which SDK 58 APIs to use and the traps in this repo's jest-expo setup. Every key API was checked against SDK 58 docs, and the risky ones were also run as temporary jest probes in `virtumetry/` (all probe files deleted afterwards; the working tree is clean).

Three findings change how the plans must be built:
1. **Reanimated 4.7 does not load in jest as configured today.** Importing it throws `Cannot read properties of undefined (reading 'loadUnpackersWithCode')`. The fix is to add `"resolver": "react-native-reanimated/jest/resolver"` and a `setupFilesAfterEnv` file that calls `require('react-native-reanimated').setUpTests()`. With that config the full existing suite (30 suites / 341 tests) still passes. This has to be Wave 0, before any primitive uses Reanimated.
2. **react-native-gesture-handler 3 breaks under that resolver in jest.** `Gesture.Pan` / `GestureHandlerRootView` crash with "[Worklets] `getUIRuntimeHolder` is not supported on web". Use core `PanResponder` for toast swipe-to-dismiss and don't add `GestureHandlerRootView` (this is a HOW deviation from UI-SPEC §9.1/§9.2; the behaviour is unchanged).
3. **A toast host rendered in the root layout sits under native iOS modals.** That covers capture (`fullScreenModal`) and share/retry (`modal`), and those are exactly where "Link created", "Link turned off" and "Couldn't discard" fire. Wrap the host in `FullWindowOverlay` from `react-native-screens` on iOS. It is already installed and works in jest.

Other verified facts:
- Two `Stack.Protected` guards (tabs: `signedIn && onboarded`; onboarding: `signedIn`) send a first-run user to `/onboarding`.
- Flipping the onboarded flag does **not** navigate, so the onboarding screen must call `router.replace('/')`.
- Replay via `push('/onboarding')` + `back()` works.
- The "silent" delete failure in UI-SPEC §7.2/§9.3 is actually an `Alert.alert` in `src/lib/api.ts`, and `library-actions.test.tsx` asserts it.

**Primary recommendation:** Plan Wave 0 as test infrastructure: jest resolver + setUpTests, global mocks, and install `expo-haptics` + the two font packages. Then build tokens and primitives, then screens. All motion goes through one reactive `useReduceMotion()` hook and the token durations, and shared values use `.get()/.set()` because React Compiler is on.

### Pattern 1: Import-free tokens shared with the DOM viewer
- `src/design/tokens.ts` has zero imports (UI-SPEC §1.6).
- `src/viewer/tokens.ts` becomes `export { tokens as VT } from '../design/tokens';`. Use a **relative** path: every existing `src/viewer/*` file uses relative imports only [VERIFIED: grep], so no alias resolution in the DOM bundle is needed.
- The viewer has **66 `VT.` references** in `world-viewer.tsx` that move to the new shape (`VT.color.*`, `VT.space.*`, `VT.radius.*`, `VT.font.css.*`). Plan it as its own task.

### Pattern 2: Reactive Reduce Motion + token durations
- Reanimated `useReducedMotion()` is **not reactive**. It "returns a boolean indicating whether the reduced motion setting was enabled when the app started" [CITED: docs.swmansion.com/react-native-reanimated/docs/guides/accessibility]. In jest it returns `false` [VERIFIED: probe].
- All Reanimated animations default to `ReduceMotion.System`. When the setting is on, `withTiming` jumps to `toValue`, entering/layout animations "instantaneously reach their endpoints", and exiting animations are omitted [CITED: same].
- So "instant" in UI-SPEC §11 comes for free. The **"fade 150 only"** rows (toast, coach mark) need an explicit branch: read our own hook and run an opacity-only `withTiming(..., { duration: 150, reduceMotion: ReduceMotion.Never })`.

```ts
// src/design/motion.ts
import { useEffect, useState } from 'react';
import { AccessibilityInfo } from 'react-native';
import { Easing } from 'react-native-reanimated';
import { motion } from './tokens';

export function useReduceMotion() {
  const [on, setOn] = useState(false);
  useEffect(() => {
    AccessibilityInfo.isReduceMotionEnabled().then(setOn);
    const sub = AccessibilityInfo.addEventListener('reduceMotionChanged', setOn);
    return () => sub.remove();
  }, []);
  return on;
}
export const ease = {
  outQuart: Easing.bezier(...motion.easing.outQuart),
  outExpo: Easing.bezier(...motion.easing.outExpo),
  inQuart: Easing.bezier(...motion.easing.inQuart),
};
```
Tests force reduced motion with `jest.spyOn(AccessibilityInfo, 'isReduceMotionEnabled').mockResolvedValue(true)` [VERIFIED: `isReduceMotionEnabled` resolves in jest].

### Pattern 3: React Compiler is ON (`experiments.reactCompiler: true`)
Use `sv.get()` / `sv.set(v)` instead of `sv.value` in component code. Reanimated's useSharedValue docs say to avoid `.value` under the React Compiler. Never read a shared value during render [CITED: docs.swmansion.com/react-native-reanimated/docs/core/useSharedValue].

### Pattern 4: Layout animations on wrappers
Put `entering`/`exiting`/`layout` on an `Animated.View` wrapper, not on a view whose `style` animates `opacity`. Reanimated warns "Property "opacity" … may be overwritten by a layout animation" [VERIFIED: probe]. For Library rows use `Animated.FlatList` with `itemLayoutAnimation={LinearTransition.duration(200).easing(ease.outQuart)}` and `entering`/`exiting` on each row wrapper.

What this means for the plan:
- **The onboarding screen must call `router.replace('/')` after `markOnboarded()`.**
- **A screen may appear in only one Protected group** ("❌ Not allowed: duplicate screen") [CITED: docs.expo.dev/router/advanced/protected].
- When a guard flips true→false, the user is redirected and that screen's history entries are removed [CITED: same].
- `redirectTo` exists (SDK 58+), but this flow doesn't need it.
- Use typed routes for replay: `router.push({ pathname: '/onboarding', params: { replay: '1' } })`.

### Pattern 6: Flags store (SecureStore sync, web-safe)
Copy `src/capture/prep-flags.ts`: try/catch around `SecureStore.getItem/setItem/deleteItemAsync`, because SecureStore is unavailable on web. Add a tiny module store with `useSyncExternalStore` so `AuthedLayout` re-renders on `markOnboarded()`. On web, return `true` for onboarded (UI-SPEC §8.1). jest already has an in-memory SecureStore mock with `__reset()` (`jest.setup.ts`).

### Pattern 7: Toast host above native modals
```tsx
import { Fragment } from 'react';
import { Platform } from 'react-native';
import { FullWindowOverlay } from 'react-native-screens';
const Overlay = Platform.OS === 'ios' ? FullWindowOverlay : Fragment;
// <ToastProvider>{children}<Overlay><ToastHost /></Overlay></ToastProvider>
```
- On iOS, native-stack modals live in a separate view controller above the root, so a root-level host renders underneath them [CITED: getstream.io chat-in-modals; github.com/calintamas/react-native-toast-message/issues/494].
- `FullWindowOverlay` renders directly under the window. It works in jest (renders children; queries find them) [VERIFIED: probe].
- Touch pass-through outside the toast and on-device behaviour in Expo Go are **MEDIUM**. Add a manual check. Fallback: mount a `ToastHost` inside `capture/_layout.tsx` and `world/_layout.tsx`.
- `useSafeAreaInsets` throws without a provider. Use the global jest mock (below).

### Pattern 8: Toast a11y and swipe
- Call `AccessibilityInfo.announceForAccessibility(msg)` when shown. This matters on iOS; on RN-web it is a no-op [VERIFIED: react-native-web source].
- Add `accessibilityLiveRegion="polite"`. On Android it is native; on web it maps to `aria-live` [VERIFIED: react-native-web createDOMProps].
- Swipe-up: `PanResponder.create({ onMoveShouldSetPanResponder: (_, g) => Math.abs(g.dy) > 4, onPanResponderRelease: (_, g) => { if (g.dy < -24 || g.vy < -0.5) dismiss(); } })`. PanResponder `vy` is px/ms, so 0.5 ≈ UI-SPEC's 500 px/s.
- Screen-reader duration ×2: `AccessibilityInfo.isScreenReaderEnabled()`.

### Pattern 9: DOM viewer props for coach marks and haptics
- Allowed props: serializable values (booleans, arrays, objects). Functions must be **top-level** props, and they become native actions that are "always asynchronous" [CITED: docs.expo.dev/guides/dom-components].
- Props reach the DOM component "over an asynchronous bridge", and a change "re-render[s] the entire React tree" [CITED: same].
- So compute `coachSeen` **once** (`useState(() => [...])`) and never update it from the parent. The DOM component keeps its own local "dismissed" set and calls `onCoachSeen(id)` as fire-and-forget.
- Web: `localStorage` inside try/catch.
- `prefers-reduced-motion` already gates CSS in `world-viewer.tsx` (`matchMedia`, read once). WKWebView supports it [CITED: webkit.org/blog/7551]. Live toggling has had WebKit bugs, so it is MEDIUM.

### Pattern 10: Fonts
```ts
// src/design/fonts.ts — per-weight subpaths: the package index requires all 12 Schibsted / 9 Martian TTFs
import { SchibstedGrotesk_600SemiBold } from '@expo-google-fonts/schibsted-grotesk/600SemiBold';
import { SchibstedGrotesk_700Bold } from '@expo-google-fonts/schibsted-grotesk/700Bold';
import { MartianMono_500Medium } from '@expo-google-fonts/martian-mono/500Medium';
import { FontDisplay } from 'expo-font';
const swap = (uri: number) => ({ uri, display: FontDisplay.SWAP }); // display is web-only, ignored on native
export const FONT_MAP = { SchibstedGrotesk_600SemiBold: swap(SchibstedGrotesk_600SemiBold),
  SchibstedGrotesk_700Bold: swap(SchibstedGrotesk_700Bold), MartianMono_500Medium: swap(MartianMono_500Medium) };
```
- The per-weight subpath modules exist (`700Bold/index.js` exports one const), and the package has no `exports` map, so subpaths resolve [VERIFIED: tarball].
- Use `useFonts` from `expo-font`, which returns `[loaded, error]` [CITED: font docs].
- On web, `loadAsync` injects `@font-face`, and the default display is `AUTO` [CITED: same].
- In jest, `useFonts` resolves `loaded=true` after the first effect flush [VERIFIED: probe]. No mock is needed.
- The 2500 ms timeout uses `setTimeout`. Tests using fake timers must advance it.

### Pattern 11: Icon wrapper
- Use `<SymbolView name={{ ios, android, web }} weight="medium" size tintColor type={hierarchical ? 'hierarchical' : 'monochrome'} />`.
- A string `weight` applies on iOS. On Android/web, `getFont(weight)` ignores strings and uses the regular Material Symbols weight [VERIFIED: expo-symbols build/utils.js]. That's fine and needs no extra import.
- On web the Material font (~977 KB per weight) loads only when an `Icon` mounts [VERIFIED: SymbolView.js].
- A string `name` renders nothing on Android/web [CITED: symbols docs], so always pass the object.
- In jest, `SymbolView` renders as a host element with its props (existing tests already render it).

### Pattern 12: Haptics helper
```ts
import * as Haptics from 'expo-haptics';
import { Platform } from 'react-native';
const run = (p: () => Promise<void>) => { if (Platform.OS !== 'web') p().catch(() => {}); };
export const haptic = {
  selection: () => run(Haptics.selectionAsync),
  light: () => run(() => Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light)),
  medium: () => run(() => Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Medium)),
  success: () => run(() => Haptics.notificationAsync(Haptics.NotificationFeedbackType.Success)),
  warning: () => run(() => Haptics.notificationAsync(Haptics.NotificationFeedbackType.Warning)),
  error: () => run(() => Haptics.notificationAsync(Haptics.NotificationFeedbackType.Error)),
};
```
- expo-haptics on web is **not** a no-op: it uses the Vibration API and an iOS Safari `<input switch>` trick [VERIFIED: ExpoHaptics.web.js; CITED: haptics docs]. The explicit web guard is therefore required by D-11.
- jest-expo ships an `ExpoHaptics` native module mock [VERIFIED: jest-expo moduleMocks/expoModules.js]. Tests assert with `jest.spyOn(Haptics, 'notificationAsync')`, or spy on our `haptic` object.
- iOS Taptic does nothing in Low Power Mode, with Taptic disabled, while the iOS Camera is active, or during dictation [CITED: haptics docs].

### Anti-Patterns to Avoid
- `sv.value` in components (React Compiler).
- `useReducedMotion()` for live gating.
- Spreading animated `opacity` together with `entering`.
- RNGH gestures or `GestureHandlerRootView` this phase.
- A toast host only at the root (hidden under modals).
- Importing `@expo-google-fonts/*` from the package root.
- Setting both `fontFamily` (custom) and `fontWeight` (UI-SPEC §1.3).
- Updating DOM `coachSeen` from the parent after a dismiss (re-renders the viewer tree).
- `@/` alias imports inside `src/viewer/*`.
- `python3` in scripts (not on PATH; use `python`).

## Common Pitfalls

### Pitfall 1: Reanimated import crashes jest
**What goes wrong:** Any test importing a Reanimated primitive fails at import.
**Why it happens:** jest-expo resolves `react-native-worklets` native files.
**How to avoid:** Add these to `package.json` `jest`: `"resolver": "react-native-reanimated/jest/resolver"` and `"setupFilesAfterEnv": ["<rootDir>/jest.setup-after.ts"]`, where the file contains `require('react-native-reanimated').setUpTests();` [CITED: docs.swmansion.com/react-native-reanimated/docs/guides/testing]. Verified: the full suite passes (30/30, 341 tests). Then `jest.useFakeTimers()` + `jest.advanceTimersByTime()` and `expect(el).toHaveAnimatedStyle({ opacity: 1 })` work [VERIFIED: probe]. Animated `react-native-svg` props (`createAnimatedComponent(Circle)`) also rendered fine, so the docs' optional `jest.mock('react-native-svg', …)` line is **not** needed.
**Warning signs:** `loadUnpackersWithCode` error.

### Pitfall 2: RNGH under the Reanimated resolver
**What goes wrong:** `[Worklets] getUIRuntimeHolder is not supported on web` fires as an uncaught failure after the test. Adding `react-native-gesture-handler/jestSetup` in setupFiles did not fix it [VERIFIED: probe].
**How to avoid:** Use `PanResponder`. Don't add `GestureHandlerRootView`.

### Pitfall 3: Toasts invisible on modal screens (iOS)
See Pattern 7. Manual device check required: share sheet "Link created" and Review "Couldn't discard".

### Pitfall 4: Onboarding never leaves
The flag flip does not navigate (Pattern 5). Call `router.replace('/')`, or `router.back()` for replay.

### Pitfall 5: Delete-failure Alert lives in `src/lib/api.ts`
**What goes wrong:** UI-SPEC §7.2/§9.3 calls the delete failure "silent rollback". The real code is `useDeleteWorld().onError`, which calls `Alert.alert("Couldn't delete", 'The scan is back in your library. Check your connection and try again.', [{ text: 'Back to Library' }])`, and `library-actions.test.tsx` (~line 300) asserts it.
**How to avoid:** Replace it with `toast.error("Couldn't delete. Check your connection and try again.")` in `api.ts` itself. `toast` is callable outside React, so there's no double feedback in the screen. Update that test to assert the toast text with `ToastProvider` rendered (or spy on `toast.error`). This is Alert #11 in the inventory.

### Pitfall 6: `useNetworkState` in jest
**What goes wrong:** It returns `{}` first, then the native mock resolves `undefined`, and unmount throws `listener.remove is not a function` [VERIFIED: probe; source `Network.js`].
**How to avoid:** Add a global mock in `jest.setup.ts`: `jest.mock('expo-network', () => ({ useNetworkState: jest.fn(() => ({ isConnected: true, isInternetReachable: true })) }))`. Offline tests override it with `mockReturnValue`. In app code use `state?.isInternetReachable === false`.

### Pitfall 7: `useSafeAreaInsets` without a provider throws
**How to avoid:** Add a global `jest.mock('react-native-safe-area-context', () => require('react-native-safe-area-context/jest/mock').default)`. Verified: the whole suite still passes with it and the expo-network mock (30/30). `world-screen.test.tsx`'s local mock still overrides it.

### Pitfall 8: Dead-control test cannot read `onPress` from host elements
**What goes wrong:** In RNTL v14, `getAllByRole('button')` returns host Views whose props are only responder handlers and `onClick`. A Pressable with and without `onPress` looks identical [VERIFIED: probe].
**How to avoid:** Scope a wrapper mock in `no-dead-control.test.tsx` (verified working):
```ts
jest.mock('react-native/Libraries/Components/Pressable/Pressable', () => {
  const React = require('react');
  const Real = jest.requireActual('react-native/Libraries/Components/Pressable/Pressable').default;
  return { __esModule: true, default: React.forwardRef((p: any, ref: any) =>
    React.createElement(Real, { ...p, ref, 'data-has-press': typeof p.onPress === 'function' })) };
});
// then: for (const b of screen.getAllByRole('button')) expect(b.props['data-has-press']).toBe(true)
```
Only `Pressable` is used for buttons in `src/` (no Touchable*, no RN `Button`) [VERIFIED: grep]. Accessible name = `accessibilityLabel` or the text content of children.

### Pitfall 9: Font timeout plus fake timers
The splash rule waits up to 2500 ms. No existing test renders `_layout.tsx` [VERIFIED: grep], so only the new onboarding/router tests are affected. Mock `useFonts` or advance timers there.

### Pitfall 10: Hex/dash grep false positives
- Hex test: scan the whole file (comments included; stricter is fine). Allow-list `src/design/tokens.ts`, `src/__tests__/**`, `src/capture/fixture-*.ts`.
- Current hits to migrate: `constants/theme.ts`, `viewer/tokens.ts`, `coverage-map.tsx`, `rename-modal.tsx`, `capture/scan.tsx`, `viewer/world-viewer.tsx` [VERIFIED: grep].
- Dash test: use the TS AST so comments with "—" (many exist) don't fail.
- Current user-facing dash literals: `src/capture/readiness.ts` (3) and `src/library/display-state.ts` (1) only [VERIFIED: grep]. The `≈` hits are in viewer tests and measure formatting; check `formatDistance` output isn't user-facing `≈` before the test bans it (UI-SPEC bans only `—`, `–`, `--`).

### Pitfall 11: NativeTabs on iOS 26
On iOS 26 the system draws the tab bar background, so `backgroundColor` and `blurEffect` have no effect [CITED: docs.expo.dev/versions/v58.0.0/sdk/router/native-tabs]. `tintColor`, `iconColor: { default, selected }`, `labelStyle: { default, selected }` are supported props. Verify their look on device. `indicatorColor` is Android/Web only.

### Pitfall 12: Icon/splash expectations in Expo Go
"Expo Go renders your app icon while the splash screen is visible". Test splash in a preview/production build [CITED: docs.expo.dev/develop/user-interface/splash-screen-and-app-icon]. Removing `ios.icon` makes iOS use the top-level `icon` (the docs say `ios.icon` "overrides the top-level icon key"). The icon PNG must be square, opaque and full-bleed [CITED: same].

### String-literal scan (em dash test)
```ts
import ts from 'typescript';
function literals(file: string, src: string): string[] {
  const sf = ts.createSourceFile(file, src, ts.ScriptTarget.Latest, true, ts.ScriptKind.TSX);
  const out: string[] = [];
  const visit = (n: ts.Node) => {
    if (ts.isStringLiteral(n) || ts.isNoSubstitutionTemplateLiteral(n) || ts.isTemplateHead(n) ||
        ts.isTemplateMiddle(n) || ts.isTemplateTail(n) || ts.isJsxText(n)) out.push(n.text);
    ts.forEachChild(n, visit);
  };
  visit(sf);
  return out;
}
// expect(no literal matches /—|–|--/) across src/app, src/components, src/library, src/capture, src/viewer (excluding __tests__)
```
