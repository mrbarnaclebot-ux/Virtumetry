## What changed

- **Sign-in:** top offset 64, BrandMark 48, "Virtumetry" display header, tagline, session-ended info Banner, offline neutral Banner ("You're offline. Connect to log in."), Email/Password TextFields (return-key chaining, non-editable while submitting), inline error under the password field (alert glyph, danger, polite live region, iOS announce, `haptic.error()`), primary lg "Log in" disabled until both fields are filled, busy "Logging in…". COPY strings and auth logic unchanged.
- **Share page:** checking = BrandMark 40 + 160 px indeterminate bar in `share-checking` ("Opening room"); not found = linkOff glyph, no action; error = alert glyph + secondary "Try again"; gate = raised card (radius lg, padding 24, max 400) with a lock glyph in a 48 overlay circle, TextField "Password", WRONG/LIMITED unchanged, primary "Open room"/"Opening…"; brand lockup footer (mono, not a link); opened = 44 scrim.hud top bar with mark 20 + heading title (1 line); crashed = "The viewer stopped working" + "Reload page". Suspense fallback is also an indeterminate bar. Head/robots, generateMetadata, data loading, re-open logic and Pattern 10 unchanged.
- **Tests:** sign-in gains disabled-state, offline banner (and unknown reachability), and error-haptic cases. share-web-route asserts the checking label/progressbar, the error body, gate body copy, and mocks `expo-symbols` so any Icon render on the page throws.

## Deviations from Plan

1. **[Rule 3] Gate aria wiring via TextField.** TextField (06.1-05) has no label nativeID prop, so `aria-labelledby="share-pw-label"` could not point at its label. The input is named by TextField's `accessibilityLabel` (aria-label "Password") and the error is linked through TextField's own `aria-describedby` + `nativeID` (useId). Same accessible result; editing text-field.tsx was outside this plan's files.
2. **TDD note:** tests were added alongside the implementation in the same commit per task (no separate RED commit).
3. Added testID `share-checking-bar` on the checking ProgressBar so the test can assert its role (RNTL `getByRole` skips non-accessible Views).
