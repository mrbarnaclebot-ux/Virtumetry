## 1. Tokens: `src/design/tokens.ts` (single source, import-free)

Rules:
- Zero imports, plain `as const` objects. Imported by RN code, by the `'use dom'` viewer (`src/viewer/world-viewer.tsx`) and by the web page.
- The **only** file in `src/` allowed to contain hex or `rgb(a)(` colour literals. A jest test (`design-tokens.test.ts`) greps `src/**/*.{ts,tsx}` for `/#[0-9a-fA-F]{3,8}\b|rgba?\(/` and fails on any hit outside `src/design/tokens.ts`, `src/__tests__/**`, `src/capture/fixture-*.ts`. The same test recomputes every ratio in §1.2 from the token values and asserts the thresholds.

Rules:
- Custom faces set `fontFamily` only, never `fontWeight` (iOS falls back to system when both are set). System roles set `fontWeight` only.
- All Text renders through `ThemedText` (§3), which applies the token's cap automatically. Viewer/HUD chrome (camera, splat) overrides to cap **1.3** for every role (prior contracts).
- Numbers inside mixed sentences ("Uploading · 40%") stay in `label`/`body` with `fontVariant: ['tabular-nums']`; only standalone values use mono.
- Weights in use: Schibsted 600/700, System 400/500/600, Martian 500. **Checker note:** Round 0 (binding) defines this 10-role product scale; the template's "3-4 sizes / 2 weights" is satisfied per face family for the core UI set (body 17, label 15, caption 13, heading 20; regular 400 + semibold 600). The 500 label weight and mono roles are binding Round 0 decisions.

**Risk 2 resolved (Martian Mono width).** Measured from the TTF: advance = **0.70 em**. `readoutLarge` at cap 1.4 = 27.4 pt per char. "~1,800 credits" would be 384 pt (> 361 pt content width on a 393 pt screen). Contract: `readoutLarge` renders **the number only** ("~930", "$9.30", "2.41 m": ≤ 165 pt at cap), the unit follows as a nested `label`/`body` Text (`<Text style={readoutLarge}>~930<Text style={body}> credits</Text></Text>`, so `getByText('~930 credits')` still matches). Every `readoutLarge` also sets `numberOfLines={1}` + `adjustsFontSizeToFit` + `minimumFontScale={0.75}` as a guard. `readout` 15 at cap 1.4: "1,500 of 1,500 files" = 294 pt, fits. Titles: "Approve processing" at `title` cap 1.3 = 361 pt, so titles may wrap to 2 lines (never `numberOfLines={1}` on titles except the viewer top bar).

### 1.4 Spacing, radii, elevation, targets

Spacing (multiples of 4): `space = { xs: 4, sm: 8, md: 12, lg: 16, xl: 24, xxl: 32, xxxl: 48, huge: 64 }`.

| Token | Value | Usage |
|---|---|---|
| xs | 4 | icon-to-text gaps, progress bar to text |
| sm | 8 | inside chips, between label and field |
| md | 12 | inside groups between stacked lines, list row vertical rhythm |
| lg | 16 | page gutter, group padding, toast margin |
| xl | 24 | between blocks inside a section |
| xxl | 32 | between sections |
| xxxl | 48 | before primary empty-state CTA, onboarding text-to-dots |
| huge | 64 | sign-in top offset |

Exceptions: 2 px progress gap is replaced by 4; legacy `Spacing.half` (2) is removed (only use: share row text gap → `xs`). Icon-only targets are 44×44 regardless of glyph size. Hairlines use `StyleSheet.hairlineWidth`.

Radii: `radius = { sm: 8, md: 12, lg: 16, xl: 28, pill: 999 }`. sm: thumbnails, small chips, plan image. md: buttons, inputs, banners, toasts, coach marks. lg: groups/cards, HUD bottom panel top corners, dialog. xl: onboarding/empty art panel. pill: mode bar, status chips, page dots.

Elevation (dark UI = lighter surface + hairline, not shadow):

| Level | Surface | Border | Shadow |
|---|---|---|---|
| 0 | `bg` | none | none |
| 1 | `surface.raised` | 1 px `hairline` only when it sits on another level-1 surface (inputs inside groups) | none |
| 2 | `surface.overlay` | 1 px `hairline` (coach mark: 1.5 px `accent`) | `shadowColor: color.shadow, shadowOpacity: 0.45, shadowRadius: 24, shadowOffset: {0, 8}`, Android `elevation: 6`. Toasts, coach marks, rename dialog only |

Targets: `minTarget = 44`. Primary/secondary Buttons are 52 tall; compact buttons and icon buttons 44.

Layout: `layout = { gutter: 16, maxContent: 800, maxForm: 480 }`. Lists use `maxContent`; sign-in, sheets on wide web and the web gate card use `maxForm`.

## 3. Font loading (Risk 3 and 4 resolved)

**App (Expo Go, iOS):** `src/design/fonts.ts` exports `FONT_MAP = { SchibstedGrotesk_600SemiBold, SchibstedGrotesk_700Bold, MartianMono_500Medium }` imported from `@expo-google-fonts/schibsted-grotesk` and `@expo-google-fonts/martian-mono` (3 files only). `RootLayout` calls `useFonts(FONT_MAP)` once (above the Public/Authed split). Splash rule in `AuthedLayout`: keep returning `null` (splash held, `preventAutoHideAsync` already called) until `(fontsLoaded || fontError || fontTimedOut) && !sessionPending`; then `SplashScreen.hideAsync()`. `fontTimedOut` flips after **2500 ms** via a `setTimeout` in a `useEffect`. On timeout or error the app renders with whatever loaded; unloaded custom families fall back to the system font (accepted; no crash).

**Web share page (`PublicLayout`):** calls the same `useFonts` but does **not** wait: render immediately (fonts swap in; `expo-font` web injects `@font-face`). No render blocking for a visitor.

**Viewer DOM component:** CSS uses `font.css.*` stacks. On the web share page the viewer renders in the same document, so the families loaded by `expo-font` resolve. Inside the native WebView (app) they are not registered and the stack falls back to `system-ui` / `ui-monospace` (SF Mono): accepted per Round 0 risk 4. Bundling fonts into the WebView is deferred to Phase 7 (§15).
