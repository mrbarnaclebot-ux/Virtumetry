# Phase 06.1: Code Review Report

**Reviewed:** 2026-11-26
**Depth:** standard
**Files Reviewed:** 68

## Summary

I reviewed the phase diff (`16f4b19^..HEAD`) for the 06.1 UI/UX makeover. That covers the token and design modules, the new `ui/` primitives, the toast and coach-mark stores, first-run flags and the onboarding guard, every restyled screen, the `'use dom'` viewer (reveal, coach marks, HUD) and the public share page.

The high-risk areas mostly hold up:
- **WebView bridge:** values coming back from the viewer are allow-listed before use (`onCoachSeen`, `onHaptic`).
- **SecureStore keys:** keys are validated (`revealKey` regex; `vm.coach.capture-prep` is a valid key).
- **Public share page:** `PublicLayout` never mounts the session, toasts or onboarding.
- **Timers:** viewer timers and listeners are cleaned up.
- **Onboarding guard:** finishing onboarding and calling `router.replace('/')` works. It is covered by a `renderRouter` test, so there is no guard loop.
- **Secrets:** none found in the diff.

Four defects remain:
- The new `useOnboarded` hook crashes server rendering of every non-share web route.
- "Replay intro" does not fully reset coach marks during the current session.
- A library thumbnail that fails to load once never comes back.
- The viewer's mode segments are below the 44 pt target.

No BLOCKER-level defects were found on the native app path or the `/r/[slug]` path.

## Warnings

### WR-01: `useOnboarded` has no server snapshot, so server rendering of every non-`/r` web route throws

**File:** `virtumetry/src/design/first-run.ts:62` (used by `virtumetry/src/app/_layout.tsx:68`)
**Issue:** `useSyncExternalStore(subscribe, getOnboarded)` is called without a `getServerSnapshot`. `app.json` sets `web.output: "server"`, and the current `dist/` has no prebuilt HTML. HTML routes are therefore rendered per request by `dist/server/_expo/server/render.js`.

On the server, `RootLayout` sends every route except `/r/*` to `AuthedLayout`, which calls `useOnboarded()` on every render, including before its `if (!ready) return null`. React's server renderer throws `Missing getServerSnapshot, which is required for server-rendered content`. I confirmed this with `react-dom/server` 19.3 in this repo. So `/`, `/sign-in`, `/settings` and the rest fail to render on the web deployment.

The share page still works because `PublicLayout` skips the hook. The toast and coach-mark stores pass a server snapshot, so this one is an oversight.
**Fix:**
```ts
export const useOnboarded = () => useSyncExternalStore(subscribe, getOnboarded, getOnboarded);
```
(`getOnboarded` already returns `true` on web.) Then check by requesting `/` on a local `expo serve` of the export.

### WR-02: "Replay intro" does not re-arm the capture coach mark for the rest of the JS session

**File:** `virtumetry/src/design/first-run.ts:73-79`, `virtumetry/src/components/ui/coach-mark.tsx:14,35,62`
**Issue:** `resetCoachMarks()` deletes the SecureStore keys. But `CoachMark` also gates on the module-level `done` Set (`want = visible && !seen && !done.has(id)`), and that Set is only cleared by `__resetCoachLockForTest`.

Suppose the user dismisses the capture-prep tip (or presses Start, which calls `dismissCoach`) and later taps Settings > "Replay intro". The row's subtitle says "Shows the intro and tips again", but the tip will not show again until the app is killed. The settings test passes only because it checks the store keys, not the next render.
**Fix:** Have the reset clear the in-memory state too. For example, export `resetCoachSession()` from `coach-mark.tsx` (`done.clear(); lock = { active: null, leaving: false }`) and call it from `replayIntro`. Or move `done` into `first-run.ts` so `resetCoachMarks` clears it.

### WR-03: A library thumbnail that fails once stays hidden after its URL is refreshed

**File:** `virtumetry/src/components/library-row.tsx:80,111-119`
**Issue:** `imageFailed` is a boolean that is never reset. The row key is stable (`world.id`), but `assets.thumbnail_url` is a presigned URL that changes on every list refetch. One failure hides the thumbnail for as long as the row stays mounted, even after a fresh, valid URL arrives. That failure can come from a load while offline, an expired presign or a transient R2 error.

The viewer already solved the same problem for the floor plan by keying failure to the URL (`planFailedUrl`, review-2 WR-01). The row does not.
**Fix:**
```tsx
const [failedUrl, setFailedUrl] = useState<string>();
const imageFailed = !!thumbnailUrl && failedUrl === thumbnailUrl;
// ...
onError={() => setFailedUrl(thumbnailUrl)}
```

### WR-04: Viewer mode segments are 36 px tall, below the project's 44 pt target

**File:** `virtumetry/src/viewer/world-viewer.tsx:1045-1058` (segment), `1033-1044` (modeBar)
**Issue:** The Orbit, Walk and Measure buttons are `height: 36` inside a 44-tall bar with 4 px padding. The bar padding is not part of the button, so the tap target is 36 px.

The RN `SegmentedControl` handles the same design with `hitSlop={4}` to reach 44. The DOM viewer has no such compensation. This is the main control in the viewer, on both the app and the public web page, and it goes against the UI-SPEC 44 pt minimum.
**Fix:** Make the segment fill the bar and inset the selected fill visually. For example, set `height: 44` on the segment with `padding: 0` on `modeBar`, and draw the pill with an inner `box-shadow: inset 0 0 0 4px <bar colour>` or a pseudo-element. Or extend the hit area with a transparent `::before { inset: -4px 0 }` on `.vm-seg`.

## Info

### IN-01: First-run flags are cached as "not onboarded" when the SecureStore read fails

**File:** `virtumetry/src/design/first-run.ts:14-20,37-40`
**Issue:** `read()` turns any `getItem` exception into `false`, and `getOnboarded` caches the result for the whole session. A keychain read that fails sends an already-onboarded user back through onboarding until the app restarts. One example is a background relaunch while the device is locked, once uploads run in a dev build.
**Fix:** Don't cache on error. Have `read` return `null` on exception and leave `onboarded` as `null`, so the next render reads again. Alternatively, fail open to the Library.

### IN-02: `useReduceMotion` returns `false` on the first render of every component

**File:** `virtumetry/src/design/motion.ts:8-21`
**Issue:** Each mount starts at `false` and flips after the async `isReduceMotionEnabled()` call. Every new `ToastView`, `Callout`, `Dot`, `ReadyPulse` and the Library's `entering` animations first run their full-motion branch. Reanimated's default `ReduceMotion.System` mostly masks this. But the specified reduced paths (150 ms opacity-only toast and coach fades with `ReduceMotion.Never`) never run on entry, and `useSharedValue(reduce ? 0 : -16)` always seeds -16.
**Fix:** Keep a module-level value that is primed once at import and updated by the `reduceMotionChanged` listener, and read it through `useSyncExternalStore`.

### IN-03: `lib/api.ts` now imports the toast host module, which the public share page pulls in

**File:** `virtumetry/src/lib/api.ts:4`, `virtumetry/src/app/r/[slug].tsx:14`
**Issue:** `r/[slug].tsx` imports `ApiError` from `@/lib/api`. Through that import it now also loads `components/ui/toast` (react-native-screens, Reanimated, expo-symbols, haptics) as well as the auth client. Nothing is mounted, so the D-19 rule still holds. But the public bundle and its server render depend on modules that the "no toasts" rule is meant to keep out.
**Fix:** Move `ApiError` (and other plain helpers) into a dependency-free `lib/api-error.ts`, and import that from the share page.

### IN-04: Floor-plan teleport surface and the mode radiogroup are not keyboard-operable on web

**File:** `virtumetry/src/viewer/world-viewer.tsx:588-597,751-768`
**Issue:**
- The plan image is a `div role="button"` with no `tabIndex` and no key handler, so keyboard users can't teleport.
- `role="radiogroup"` with `role="radio"` buttons implies arrow-key roving focus, but none is implemented. Every radio is a separate tab stop.

**Fix:** For the plan, either give the `div` `tabIndex={0}` and an Enter/Space handler, or drop the button role and add a caption explaining it. For the modes, either add arrow-key handling, or change the roles to `button` with `aria-pressed`.

### IN-05: The rename dialog for an unnamed scan is prefilled with its date and time

**File:** `virtumetry/src/app/(tabs)/index.tsx:486`, `virtumetry/src/library/display-state.ts:156`
**Issue:** `setRenaming({ id, title: state.displayTitle })` now passes the `scanTitle` fallback (for example "Nov 26, 2026, 3:04 PM") as the editable name. Save stays disabled until the text changes. Any partial edit then stores a date string as the real title.
**Fix:** Pass the raw `item.title ?? ''` to `RenameModal`, and keep `displayTitle` for the dialog's context and accessibility only.

### IN-06: The "just ready" pulse replays whenever a row remounts

**File:** `virtumetry/src/app/(tabs)/index.tsx:545-557,666`
**Issue:** `track.ready` only grows, so `justReady` stays `true` for the rest of the screen's life. When FlatList virtualizes a row away and back, `ReadyPulse` mounts again and replays. The "first ready moment" then repeats.
**Fix:** Remove the id from `track.ready` after the pulse has played, for example with a timeout or an `onDone` callback from `ReadyPulse`.

### IN-07: The share page's open chain can set state after the slug changes or the page unmounts

**File:** `virtumetry/src/app/r/[slug].tsx:110-122`
**Issue:** The `live` guard is only checked before `open()` is called. `open()` itself calls `setState({ k: 'opened' })` after awaiting `openPublicShare`. If the slug changes while that request is in flight, the previous room can overwrite the new one. This is rare on a single-slug page.
**Fix:** Have `open` return the data, and only call `setState` in the effect when `live` is still true.
