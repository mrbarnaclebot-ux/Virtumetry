<decisions>
## Implementation Decisions

### Theme & tokens (UX-01)
- **D-01:** **Dark-only.** The palette is a dark palette; `app.json` `userInterfaceStyle` becomes `"dark"`, the light theme branch is removed, `useTheme()` returns the single dark theme (keep the hook signature so call sites change minimally). Navigation `ThemeProvider` gets a custom theme built from the tokens (no `DefaultTheme`).
- **D-02:** **One import-free token module** `src/design/tokens.ts` (pure constants, zero imports, so the `'use dom'` viewer can import it). It holds colors (palette + derived surfaces/borders/states/scrims/overlays), type scale, spacing, radii, elevation, motion durations/easings, min target. `src/constants/theme.ts` re-exports/derives `Colors`, `Spacing`, `Fonts` from it (keeps existing imports working); `src/viewer/tokens.ts` `VT` becomes a thin alias of it so there is exactly one source of hex values. A test asserts no hex literals outside the token module in `src/` (allow-list tests/fixtures) and that every text/background pair used meets WCAG AA (4.5:1 body, 3:1 large text/UI).
- **D-03:** Palette roles: `background #060a0a` = app canvas; `text #e7f2f2` = primary text; `primary #a2cccb` = main CTA fill / focus / active state (dark text on it); `secondary #3e4a71` = secondary surfaces, chips, selected rows; `accent #6b6cae` = highlights, progress, coach marks, brand gradient partner. Derived: elevated surfaces from background toward secondary, muted text checked for AA, borders/hairlines, success/warning/danger tuned to the palette and passing AA on surfaces. `accent #6b6cae` on `#060a0a` is about 4:1, so it is used for large text/icons/fills only, not small body text (UI-SPEC computes exact ratios).

### Typography, icons, assets (UX-02)
- **D-04:** Typography designed with the `impeccable` skill: a distinctive but legible pairing loadable in Expo Go via `expo-font` + `@expo-google-fonts/*` (display face for headings, a readable text face or system for body/UI), with scale, weights, tracking, line-heights and `maxFontSizeMultiplier` caps. Viewer DOM + web page load the same faces (CSS `@font-face` from the bundled font assets or a clean system fallback).
- **D-05:** Icons: **SF Symbols via `expo-symbols`** on iOS (installed); one small `Icon` wrapper with a web/Android fallback (`@expo/vector-icons`, bundled with Expo) so the web share page has real icons. The viewer DOM component uses inline SVG icons (it cannot use RN components).
- **D-06:** **Higgsfield balance at phase start = 0.18 credits (plan "lite")**, i.e. effectively zero, so **no Higgsfield generations** this phase (record 0 generations / 0 credits in the SUMMARY). Assets are made locally: brand mark + onboarding/empty-state illustrations as **`react-native-svg` vector components** (Expo Go, crisp, tiny, themeable, animatable); **app icon + splash rendered locally** with Blender 5.0 (`C:\Program Files\Blender Foundation\Blender 5.0`, headless `blender -b -P script.py`) or Python PIL from the same geometry, optimised PNGs. No third-party logos, no SpAItial branding. `app.json` icon/splash/adaptive-icon colors updated (Expo Go shows them only partially; full effect at the Phase 7 dev build). Remove unused Expo starter images if unreferenced.

### Onboarding & coach marks (UX-03, UX-04)
- **D-07:** First-run onboarding = 3–4 swipeable pages (Scan → Check & approve → Process → Walk, measure & share) with vector illustrations, page dots, Skip and Next/Get started; shown once **after sign-in, before the Library**. Flag persisted in `expo-secure-store` (installed; versioned key e.g. `vm.onboarding.v1`). Settings gets **"Replay intro"**. Not shown on the web share page.
- **D-08:** Coach marks: one reusable `CoachMark` (anchored callout, dismissible) shown once per key (`vm.coach.<id>`): capture prep (what makes a good scan), first Walk and first Measure in the viewer. Viewer coach marks live inside the DOM component; persistence is passed in from native as a prop + callback (web share page: `localStorage`). Must be once-only and dismissible. "Replay intro" also resets coach marks.

### Toasts (UX-05)
- **D-09:** **One in-house toast system** (`ToastProvider` + `toast.success/error/info()`), built on Reanimated + safe-area (no new dependency, testable in jest). Top-anchored, auto-dismiss (about 3 s info/success, longer for error), tap/swipe to dismiss, one visible with a queue, announced to screen readers, haptic per type, Reduce Motion = fade only. Replaces informational `Alert.alert` (e.g. "Couldn't discard", copy/share success, rename saved, retry started, action errors). **Destructive confirmations stay `Alert.alert`** (discard scan, delete world, cancel scan, log out, revoke link). The web share page uses the same component where it shows transient feedback.

### Motion & haptics (UX-06)
- **D-10:** Motion via `react-native-reanimated` 4 (installed): press feedback on buttons/rows, entering/layout animations for rows and sheets, animated progress, skeleton loading, route transitions tuned per route. All gated by Reduce Motion (instant/fade). Durations/easings from motion tokens.
- **D-11:** Haptics via **`expo-haptics`** (in Expo Go; `npx expo install expo-haptics`): selection on mode/segment changes, light impact on primary actions, success/warning/error with toasts and capture milestones. One `haptics` helper (no-op on web); the haptics map lives in the UI-SPEC.

### No zombie UI (UX-07) & a11y (UX-08)
- **D-12:** Audit every screen for controls without real handlers, disabled-forever controls, placeholder copy, unreachable states and stale caches; each is wired, removed, or given an honest state. Every data screen has real loading (skeleton), empty, error (with a working retry) and offline (`expo-network`) states. A jest "no dead control" test renders key screens and asserts every `button` has an `onPress` and an accessible name. 44pt targets, AA contrast, labels, Dynamic Type caps, Reduce Motion all hold.
- **D-13:** Shared primitives (inventory in UI-SPEC): `Button` (primary/secondary/ghost/destructive, loading, haptic), `IconButton`, `Surface/Card`, `ListRow`, `StatusPill`, sheet header, `Banner`, `EmptyState`, `ErrorState`, `Skeleton`, `ProgressBar`, `Toast`, `CoachMark`, `Screen`. Reuse/replace `themed-text`, `themed-view`, `approval.tsx`, `readiness-pill`, `library-row`, `rename-modal`, `coverage-map` rather than making parallel copies.

### Delivery
- **D-14:** JS/assets only; ships in Expo Go. Native-only polish (anything needing a dev build, full icon/splash effect) is deferred to Phase 7 and listed. Web share page may be redeployed to the Expo Hosting **dev alias** with `eas deploy` (no `--prod`). No backend change expected; if one appears it deploys to Railway **dev** only.
- **D-15:** Tests: update tests for changed copy/structure; add tests for tokens/contrast, onboarding gating (shows once, skip, replay), toast (show/queue/dismiss/a11y), coach-mark once-only, no-dead-control. `npx expo lint`, `npx tsc --noEmit`, `npx jest --ci` green before done; both GitHub Actions workflows green after push.
- **D-16:** Design quality loop: `impeccable` critique folded into the UI-SPEC before planning; after execution, impeccable critique/polish passes on every screen, iterated until premium; findings and fixes per round in `06.1-CRITIQUE.md`.

### Claude's Discretion
- Exact derived color values, font pick (via impeccable), illustration style, onboarding page count, file layout under `src/design/`, per-route transitions, copy wording (honest, short, brand-voiced, never SpAItial's copy).
</decisions>
