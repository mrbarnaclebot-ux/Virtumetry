# Phase 06.1 Plan 09: Library slice Summary

The Library now runs on the design system. It shows 4 skeleton rows while loading, offline and error states with a working Try again, and a first-run empty state with art, 3 steps and a single "Scan a room" button. Offline, refresh-failed and budget banners sit above the rows, and the refresh-failed banner has a working Refresh button. Delete, rename and discard results show as toasts. The onboarding scan intent opens a new scan, and a world that turns ready pulses its row once and fires a success haptic.

## What changed

- `api.ts`: `useDeleteWorld` onError now calls `toast.error("Couldn't delete. Check your connection and try again.")`. The optimistic rollback is unchanged and the Alert import is gone. onSuccess shows `toast.success('Scan deleted')`. `useRenameWorld` onSuccess shows `toast.success('Name saved')`.
- `display-state.ts`: `Usually 30 min to 2 h`.
- `LibraryRow`: uses StatusPill (paused local uploads use the offline icon), ProgressBar `row-progress` (role and value kept), an IconButton "More actions for {title}" with the same hint as before, a 64 thumb on surface.raised with the world icon as fallback, and surface.pressed on press. The composed label, the disabled rows without a role and the 0.6 opacity on cancelled rows are kept. Optional `justReady` runs a 600 ms pulse (scale 1 to 1.25 to 1 on outQuart, plus a success ring fading 0.6 to 0). There is no pulse under Reduce Motion.
- `RenameModal`: level-2 Surface on a color.scrim.modal backdrop (the rgba literal is removed), TextField with an `n/80` helper or an inline error, ghost Cancel, and Save Name with its label in primary. Validation and labels are unchanged.
- `LibraryEmptyArt`: a 160-tall panel with radius xl and a secondary to accent gradient. It draws the brand corner at x4.5, centred on (160,86), and a dashed primary semi-ellipse path from (70,130) to (250,130). It is hidden from screen readers.
- Library screen: built from Screen and Animated.FlatList (LinearTransition plus FadeIn/FadeOut on row wrappers, all off under Reduce Motion), with a primary-tinted RefreshControl and a hairline separator inset 80. The banner zone holds at most two banners: connectivity (offline or refresh-failed with Refresh) and the budget banner, whose per-session dismissal and announcement are unchanged. Discard failure shows `toast.error("Couldn't discard. Try again.")` and success shows `toast.success('Scan discarded')`. Row menus and the discard/delete confirmations are still Alert.alert. `consumeIntent()` runs on mount and calls `newScan()`.

## Deviations from Plan

1. **Acceptance grep `grep -n "Alert" api.ts`** still matches the `BudgetAlert` type name, which is not an Alert call. The `Alert` import and the `Alert.alert` call are both gone.
2. **Separator placement**: the plan listed the hairline separator under LibraryRow. It is drawn by the screen's `ItemSeparatorComponent` (inset 80) so the last row has none.
3. **First-ready tracking**: the plan asked for a ref Map plus a module once-per-session Set, with setState called in an effect. The lint rule `react-hooks/set-state-in-effect` rejects that, so the state is now derived while rendering from the previous list. A moment can repeat only if the Library screen remounts and then sees the same world change from non-ready to ready again, which in practice doesn't happen.
4. **Header pill radius**: Button has no pill radius, so "New scan" uses radius md. Adding a pill option means editing `ui/button.tsx`, which is outside this plan's files.
5. **Tests use toast spies** (`jest.spyOn(toast, ...)`) rather than mounting ToastProvider. `__resetToastsForTest()` runs in beforeEach.
