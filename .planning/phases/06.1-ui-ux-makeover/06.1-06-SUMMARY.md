# Phase 06.1 Plan 06: Toast System and CoachMark Summary

This plan adds one in-house toast system and a reusable coach mark. `toast.success/error/info` is a module store, so it can be called from anywhere. The host sits in a FullWindowOverlay on iOS. Toasts show one at a time with a FIFO queue of at most 3, and identical messages are coalesced. Durations come from tokens and double when a screen reader is on. Toasts dismiss on tap or a PanResponder swipe-up, announce themselves, fire haptics, and fall back to a fade when Reduce Motion is on. `CoachMark` is an accent-outlined callout with a caret, shown once, and guarded by a module lock so only one shows at a time.

## Notes for downstream plans

- Mount `<ToastProvider>` once, inside SafeAreaProvider in AuthedLayout (plan 08), and never in PublicLayout (T-06.1-14). No GestureHandlerRootView is needed.
- `CoachMark` positions itself absolutely from window coordinates (`measureInWindow`), so it must sit in a full-window parent such as the scan HUD root. When the caller presses Start, it should call `dismissCoach('capture-prep')`.
- `__resetToastsForTest()` / `__resetCoachLockForTest()` belong in a `beforeEach` of any screen test that triggers them. Toast screen tests also need `jest.useFakeTimers()`, or real timers will leak.
- Test files declare a `jest.Matchers.toHaveAnimatedStyle` global typing locally, because Reanimated's matcher has no typings.

## Deviations from Plan

- **[Rule 1 - Bug] The coach lock claimed from a stale render snapshot.** If two marks mounted together, both would claim the lock. The claim effect now reads the live module `lock`.
- **[Rule 3 - Blocking] The lint rule `react-hooks/set-state-in-effect` rejected an effect-driven external dismiss.** The `leaving` state moved into the module lock, so `dismissCoach` runs the exit directly. As a result, external dismissals do not call `onDismiss` (see decisions).
- Added `testID`s: `toast` and `coach-mark` on the animated containers, for the reduced-motion style assertions.
