## Phase Goal

**As a** the owner, **I want to** have an approved scan processed by real Echo-3 exactly once, inside my budget, and retry a retryable failure only after re-confirming the cost, **so that** a paid run never double-charges and never wastes money on a bad capture.

<objective>
Vertical slice 3 (app side of retry): the owner opens a failed scan and sees either a fresh-quote "Approve and retry" sheet or plain guidance to scan again, driven only by the server's `retryable` flag. The Phase 4 approval UI is shared, not forked.

Purpose: LIB-02 / success criterion 3 (app half). Server contract per 06-UI-SPEC data contract; backend lands in 06-07, so tests mock fetch.
Output: approval.tsx (moved code), retry sheet route, api.ts client additions, failureGuidance, tests.
</objective>

| T-06-11 | Tampering (financial) | double tap / lost response creating two retries | mitigate | one Idempotency-Key per sheet open reused across presses; busy state blocks double taps; server dedupes on world_attempts.client_request_id (06-07) |
| T-06-12 | Tampering (financial) | approving a stale price | mitigate | quote never cached (gcTime/staleTime 0); server re-quotes and rejects approval below quote; app refetches on approval_below_quote |
| T-06-13 | Elevation | client deciding retryability | mitigate | UI renders only the server `retryable`; missing = not retryable; server re-checks in the route |
| T-06-14 | Information disclosure | raw failure codes shown | mitigate | only failureText/failureGuidance copy rendered; failure_message never rendered (T-03-28) |
