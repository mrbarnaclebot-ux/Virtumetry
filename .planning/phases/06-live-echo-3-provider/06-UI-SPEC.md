**Data contract the UI depends on** (planner wires these; UI renders nothing it cannot read):

- `POST /v1/worlds/:id/retry { approved_max_credits }` with `Idempotency-Key` → `{ world }` on success; 409 `not_retryable`; 400/409 `approval_below_quote`; 429 rate limited.

## Screen Contracts

**Focal points [default]:** Retryable sheet: the cost figure, then "Approve and retry". Non-retryable sheet: the guidance body, then "Scan again". Library: rows stay the focus; the banner is one compact card above them.

### A. Failed server row (`library-row.tsx`, `(tabs)/index.tsx`)

- A failed server row (`status === 'failed'`) becomes pressable (today it is `disabled`). Tap → `router.push('/world/[id]/retry')` with `id`. `accessibilityRole="button"`, hint: retryable → "Shows the cost to try again"; not retryable → "Shows what happened".
- Row visuals unchanged (`Failed · {reason}` destructive + `{charge} · {date}`). No new inline button **[default]** (keeps the row layout of Phase 3).
- Row "•••" menu for a failed server row: `Retry…` (only when `retryable`, first item, opens the same sheet) · Rename · Delete (destructive) · Cancel. Menu `accessibilityHint` stays "Rename or delete" when not retryable, "Retry, rename or delete" when retryable.
- After a successful retry, the row comes back from the poll as `submitting` / `packing` → existing `Processing · …` line; no extra UI.

### B. Retryable failure sheet (`world/[id]/retry.tsx`, `retryable === true`)

Page sheet, `Layout` from `approval.tsx` (scrolling content + pinned actions with hairline). Data: the world from the cached `useWorlds` list (fall back to `GET /v1/worlds/:id` if not cached).

```
Retry processing                              ← title 32/600
24
┌ reason card (backgroundElement, r12, p16) ┐
│ [!] Failed · Something went wrong while    │  icon 20 destructive, smallBold destructive
│     processing                             │
│ 8                                          │
│ {guidance body}                            │  default 16/400 text
│ 8                                          │
│ {charge line}                              │  small 14/400 textSecondary
└────────────────────────────────────────────┘
24
┌ quote card (identical to Phase 4) ─────────┐
│ This retry will use ~1,180 credits ≈ $X    │
│ 8  4,200 credits left today                │
│ 8  [!] over-budget line (warning, if any)  │
└────────────────────────────────────────────┘
24
This is a new paid run. Nothing is charged until you approve.   ← small textSecondary
────────── pinned actions ──────────
[        Approve and retry (52, accent)       ]
               Cancel (44)
```

- Quote: `getQuote(world.frame_count)` on open, `gcTime: 0, staleTime: 0, retry: false` (same as Phase 4: never cached, budget changes).
- Idempotency-Key: generated once when the sheet mounts with `uuid.v4()` from `expo` (already used in `src/capture/fixture-source.ts`; no new dependency) and reused for every press on this sheet, so a lost response + second tap replays the same retry **[default]**. A new sheet open = a new key.
- Primary enabled only when `quote.data.withinBudget === true` and not submitting. Press → `POST /v1/worlds/:id/retry { approved_max_credits: quote.data.credits }`.

| State | Renders |
|-------|---------|
| Loading quote | Quote card: accent `ActivityIndicator` + "Getting quote…"; primary disabled (0.4) |
| Quote error | Quote card: destructive error line + "Try again" neutral button (refetch); primary disabled |
| Over budget | Quote card shows the warning line; primary disabled with `accessibilityHint` = the warning text |
| Ready to approve | Quote card filled; primary enabled |
| Submitting | Primary shows `onAccent` spinner, `busy`; Cancel disabled (0.4); sheet swipe-down still allowed (request continues, key persists in the request) |
| Retry error: network / 5xx / 429 | Destructive line under the quote card (see copy); primary re-enabled; same key on next press |
| Retry error: price changed (`approval_below_quote`) | Destructive line; quote refetched automatically; primary enabled when the new quote is within budget |
| Retry error: 409 `not_retryable` | Destructive line; primary hidden; Cancel becomes "Close"; worlds query invalidated |
| Success | Invalidate the worlds query, announce "Retry started", `router.back()` to the Library |

### C. Non-retryable failure sheet (same route, `retryable !== true`)

```
Scan failed                                   ← title 32/600
24
┌ reason card (same as B) ┐   icon + "Failed · {reason}", 8, guidance body, 8, charge line
24
────────── pinned actions ──────────
[          Scan again (52, accent)           ]
               Close (44)
```

- No quote, no retry button, ever. "Scan again" → `router.back()` then the Library's existing `newScan()` path (prep or scan per D-11 Phase 4 flags) **[default]**: implement by `router.replace('/capture/prep')` (prep handles the skip flag itself if moved there) or by exporting `newScan` logic; planner picks the smaller diff.
- Guidance body chosen by one pure function `failureGuidance(stage, code, charged)` in `display-state.ts` (unit-tested) — see copy table.

### D. Library budget-alert banner (`(tabs)/index.tsx`)

- Shown in `ListHeaderComponent`, below the "Library / New scan" row and below the "Couldn't refresh" line, 16 above the first row, when `data.budgetAlert` is non-null and not dismissed.
- Card: `backgroundElement`, radius 12, padding 16, row layout: warning icon 20 → 8 → text column (flex 1) → 44x44 dismiss button (`xmark` 16, `textSecondary`).
- Text: line 1 `small` 14/400 `text` (percent sentence); line 2 `small` `textSecondary` (consequence), 4 gap.
- Percent = `Math.min(100, Math.floor(spent / budget * 100))`.
- Dismiss: in-memory module-level `Set` keyed `${window}` **[default]** (per app session = until the JS process restarts; no storage). A dismissed daily banner does not hide a monthly one. Dismiss is not destructive, no confirm.
- `accessibilityRole="alert"` on first appearance (iOS: `announceForAccessibility` of line 1 once per session per window); dismiss button label "Dismiss budget alert".
- Not shown in the empty/error/loading states of the Library (no data = no alert).

## Copywriting Contract

Voice (Phase 3): short, plain, second person, no exclamation marks. The user sees "scan", "room", "processing", never "world", "provider", "Echo-3" or error codes. Ellipsis is "…". Existing Phase 3/4 failure reasons (`failureText`) are reused unchanged as the "Failed · …" heading.

### Core

| Element | Copy |
|---------|------|
| Primary CTA (retryable) | Approve and retry |
| Primary CTA (non-retryable) | Scan again |
| Secondary | Cancel (B) · Close (C, and B after 409) |
| Sheet title | Retry processing (B) · Scan failed (C) |
| Row menu item | Retry… |
| Quote sentence | This retry will use ~{credits} ≈ {usd} |
| Budget remaining | {credits} left today · {credits} left this month |
| Over budget (daily) | This retry would go over today's limit. Try again tomorrow. |
| Over budget (monthly) | This retry would go over this month's limit. |
| Quote loading | Getting quote… |
| Footnote | This is a new paid run. Nothing is charged until you approve. |
| Charge line | Not charged for this run · Charged for this run · Charge unknown (same mapping as the row) |
| Success announcement | Retry started |
| Empty state | Not applicable: no new list. Library empty state ("No scans yet") unchanged |

### Errors

| Element | Copy |
|---------|------|
| Quote error | Couldn't get a quote. Check your connection and try again. / Try again |
| Retry error (network, 5xx) | Couldn't start the retry. Check your connection and try again. |
| Retry error (429) | Too many tries. Wait a minute, then try again. |
| Retry error (price changed) | The cost changed. Check the new quote, then approve again. |
| Retry error (409 not_retryable) | This scan can't be retried anymore. Close this and check its status in your Library. |
| Sheet world load error | Couldn't open this scan. Check your connection, then try again. / Try again |

### Guidance body (`failureGuidance`)

| Case | Copy |
|------|------|
| Retryable, limit codes (`BUDGET_EXCEEDED`, `QUOTE_ABOVE_APPROVAL`, `HTTP_402`/`INSUFFICIENT_CREDITS`) | Your spending limit or credits stopped this run. Check the cost below before you try again. |
| Retryable, `RATE_LIMITED` / `PROVIDER_UNAVAILABLE` / provider-side processing failure | The processing service had a problem on its side. Trying again often works. |
| Not retryable, validate/pack/upload stage or capture-validation codes | This capture can't be turned into a room. Scan again: move slowly, keep the room well lit and cover every wall. |
| Not retryable, `SUBMIT_UNCERTAIN` / `IDEMPOTENCY_KEY_REUSED` / `charged == null` | We can't tell if this run was charged, so it can't be retried from the app. Scan the room again to get a new one. |
| Not retryable, import stage | The room was built but couldn't be saved. It can't be retried from the app. Scan again to get a new room. |
| Not retryable, cancelled / anything else (unknown codes) | This scan can't be retried. Scan the room again to get a new one. |

### Budget banner

| Element | Copy |
|---------|------|
| Line 1, < 100% | You've used {n}% of today's processing budget. · You've used {n}% of this month's processing budget. |
| Line 1, 100% | You've used all of today's processing budget. · You've used all of this month's processing budget. |
| Line 2, daily | New scans may wait until tomorrow. |
| Line 2, monthly | New scans may wait until next month. |
| Dismiss label | Dismiss budget alert |

### Destructive actions

None added in this phase. Retry is a paid action, guarded by the explicit approval screen (fresh quote + "Approve and retry"), not by an `Alert`. Cancel/Close/dismiss are non-destructive. Existing Delete confirmation is unchanged.
