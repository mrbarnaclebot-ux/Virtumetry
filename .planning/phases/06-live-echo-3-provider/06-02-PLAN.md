## Phase Goal

**As a** the owner, **I want to** have an approved scan processed by real Echo-3 exactly once, inside my budget, and retry a retryable failure only after re-confirming the cost, **so that** a paid run never double-charges and never wastes money on a bad capture.

<objective>
Vertical slice 2 (the data model and the retry rule): one additive migration (`worlds.submit_attempt`, `world_attempts`, `budget_alerts`), the pure server-side `isRetryable` rule, and the purge fix that the new FK would otherwise break.

Purpose: the retry route (06-07), the alert hook (06-04) and the payload's `retryable` flag all build on these; LIB-03 purge must keep working.
Output: schema + generated migration applied to Neon dev, `src/retry.ts`, truth-table test, purge fix + test.
</objective>
