## Phase Goal

**As a** the owner, **I want to** have an approved scan processed by real Echo-3 exactly once, inside my budget, and retry a retryable failure only after re-confirming the cost, **so that** a paid run never double-charges and never wastes money on a bad capture.

<objective>
Vertical slice 4 (money-path hardening on the worker): budget alerts fire once per window when spend crosses the share, and the four submit/import gaps the research found are closed in `pipeline.ts`.

Purpose: OPS-06 / success criterion 4 (automated half) and PROC-05 correctness before any live run (401 is the likeliest first-live-run error).
Output: budget.ts alert insert + `budgetAlertFor`, pipeline.ts fixes + alert side effects, budget-alert pg test, scenarios pg test updates.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-15 | Tampering (financial) | releasing a possibly billed reservation | mitigate | release only on definitive refusal with no prior uncertain attempt; uncertain + refusal → SUBMIT_UNCERTAIN, reservation kept |
| T-06-16 | Tampering (financial) | 401 burning 4 attempts and holding funds forever | mitigate | 401 → PROVIDER_AUTH refusal on first attempt, released |
| T-06-17 | Denial of service | alert side effect failing the submit | mitigate | row insert in tx; warn/push after commit in try/catch; test with throwing push |
| T-06-18 | Repudiation | duplicate alerts | mitigate | unique (provider_mode, budget_window, window_start) + ON CONFLICT DO NOTHING under the advisory lock |
| T-06-19 | Denial of service | import wedged by optional thumbnail | mitigate | bounded 3 passes then skip with warn |
