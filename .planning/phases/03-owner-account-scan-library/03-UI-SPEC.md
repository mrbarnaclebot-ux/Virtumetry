## Spacing Scale

Values come from the existing `Spacing` tokens in `constants/theme.ts`.

| Token | Value | Usage |
|-------|-------|-------|
| xs (`Spacing.one`) | 4px | Gap between the status icon and status text, gap between the status line and the progress bar |
| sm (`Spacing.two`) | 8px | Gap between title and status line, gap between field label and input, thumbnail corner radius |
| md (`Spacing.three`) | 16px | Screen side padding, row vertical padding, gap between thumbnail and text, gap between form fields |
| lg (`Spacing.four`) | 24px | Gap between the screen title and the first content, modal padding, settings section gap |
| xl (`Spacing.five`) | 32px | Gap between the sign-in wordmark block and the form |
| 3xl (`Spacing.six`) | 64px | Sign-in top padding above the wordmark (inside the safe area) |

Fixed sizes (all multiples of 4):

| Element | Size |
|---------|------|
| Minimum touch target (every button, row, "…" button, input) | 44 x 44pt |
| Text input height | 48 |
| Primary / destructive button height | 52 (sign-in "Log in"), 44 (modal buttons) |
| Thumbnail | 64 x 64, radius 8 |
| Row minimum height | 96 (64 thumbnail + 16 top + 16 bottom) |
| Progress bar | height 4, radius 2, full width of the text column |
| Input and button corner radius | 12 |
| Separator | `StyleSheet.hairlineWidth`, inset 96 from the left (lines up with the text column) |

Exceptions: `Spacing.half` (2px) stays in the theme but is not used in this phase. No 48 token is added. Content width is capped at the existing `MaxContentWidth` (800) and centered, which only matters on web.

## Typography

Two weights only: **400 (regular)** and **600 (semibold)**.

| Role | ThemedText type | Size | Weight | Line height | Used for |
|------|-----------------|------|--------|-------------|----------|
| Body | `default` | 16px | 400 | 24 (1.5) | Input text, settings values, empty-state body, modal input |
| Body emphasis | `smallBold` → renamed role, see note | 16px | 600 | 24 (1.5) | Row title, button labels, settings row labels |
| Label | `small` | 14px | 400 | 20 (1.43) | Row status line, dates, field labels, inline errors, helper text |
| Heading | `subtitle` | 20px | 600 | 28 (1.4) | Modal title, empty-state heading, settings section heading |
| Display | `title` | 32px | 600 | 40 (1.25) | Screen titles ("Library", "Settings"), sign-in wordmark |

Note: the existing `smallBold` type becomes **16 / 600 / 24** (renamed in code to `defaultSemiBold` if the planner prefers; either is fine, but there is exactly one 16/600 style). This gives 4 sizes (14, 16, 20, 32) and 2 weights.

Rules:
- Font scaling (Dynamic Type) stays on. Use `maxFontSizeMultiplier={1.6}` on row text and buttons so rows grow but do not break. Rows grow in height. Text never truncates the status line. The row title truncates to 2 lines (`numberOfLines={2}`).
- Numbers in progress text use `fontVariant: ['tabular-nums']` so "40%" does not jitter while polling.

## Screen Contracts

**Focal points [default]:** Sign-in — the "Virtumetry" wordmark, then the accent "Log in" button. Library — each row's thumbnail + title, with the status line second. Empty state — the icon and heading. Settings — the signed-in email; "Log out" is the only destructive control.

**Dismiss labels [default]:** "Cancel" is kept on the action menu, rename modal and confirmations: it is the iOS system convention for dismissing a sheet/alert, and the paired action is always specific (Rename, Delete, Save Name, Log out).

**Spacing exceptions:** the 2px input focus border and the progress bar's 2px radius are stroke/shape values, not spacing tokens.

### 1. Root session gate (D-09)

- While the stored session is being read: keep the splash screen up (`SplashScreen.preventAutoHideAsync()` already exists; hide it once the session check resolves). No extra loading screen.
- No session → sign-in. Session → tabs (Library first).
- If any API call returns 401 while signed in, clear the session and query cache, go to sign-in, and show the session-ended notice there (copy below).

### 2. Sign-in (D-10)

Layout, top to bottom, inside `SafeAreaView`, side padding 16, `KeyboardAvoidingView` (`behavior="padding"` on iOS), content in a `ScrollView` with `keyboardShouldPersistTaps="handled"`:
1. 64 top padding
2. Wordmark "Virtumetry" (Display 32/600, `text`)
3. 8 gap, then tagline (Label 14/400, `textSecondary`)
4. 32 gap
5. Session-ended notice if present (Label, `textSecondary`), 16 gap
6. "Email" label (Label) → 8 → email input
7. 16 gap
8. "Password" label (Label) → 8 → password input
9. 16 gap
10. Inline error (Label, `destructive`), only when there is an error, then 16 gap
11. "Log in" button: full width, height 52, radius 12, accent fill, `onAccent` 16/600 label

No sign-up link and no forgot-password link anywhere.

Input behavior:
- Email: `keyboardType="email-address"`, `autoCapitalize="none"`, `autoCorrect={false}`, `autoComplete="email"`, `textContentType="username"`, `returnKeyType="next"` (moves focus to password). Value is trimmed before sending.
- Password: `secureTextEntry`, `autoComplete="current-password"`, `textContentType="password"`, `returnKeyType="go"` (submits). This lets iOS Passwords autofill.
- Input style: height 48, radius 12, `backgroundElement` fill, 16 horizontal padding, Body text, placeholder `textSecondary`. Focused: 2px `accent` border. Not focused: no border.

Button states:
- Disabled (either field empty after trim): opacity 0.4, not pressable.
- Pressed: opacity 0.8.
- Submitting: label becomes "Logging in…", `ActivityIndicator` (`onAccent`) left of the label, inputs not editable, button not pressable.
- Typing in either field clears the inline error.

### 3. Library tab (D-19, D-20, D-21)

Layout: `FlatList` with `contentInsetAdjustmentBehavior="automatic"`, side padding 16. The list header is the screen title "Library" (Display 32/600) with 16 top and 24 bottom spacing. No native stack header.

Row anatomy (min height 96, padding 16 vertical, the row is a `View`, not pressable, in this phase because there is no detail screen yet):

```
[thumbnail 64x64] 16 [title (16/600, max 2 lines)          ] [ … ]
                     8
                     [status line (14/400)                 ]
                     4
                     [progress bar (only uploading/processing with %)]
                     4
                     [secondary line: stalled hint / charge note / date]
```

- Thumbnail: `expo-image`, `contentFit="cover"`, radius 8, `transition={150}`. When there is no `thumbnail_url` (or it fails to load) show a `backgroundElement` square with `cube.transparent` in `textSecondary`. Thumbnail is decorative (`accessible={false}`).
- "…" button: 44 x 44 hit area, `ellipsis` icon 20 in `textSecondary`, pressed background `backgroundSelected` radius 22. It is vertically centered on the row.
- Date line: shown for ready, failed, cancelled and saved_on_phone: "{date}" from `created_at` via `toLocaleDateString(undefined, { month: 'short', day: 'numeric', year: 'numeric' })`, e.g. "Nov 24, 2026". Label, `textSecondary`.
- Separator between rows: hairline, `backgroundSelected`, inset 96 from the left.
- Sort: newest `created_at` first (server order; the client does not re-sort) **[default]**. Local saved_on_phone items are listed above server items.

Data states:

| State | What renders |
|-------|--------------|
| First load, no cache | Centered `ActivityIndicator` (large, accent) under the title |
| Load failed, no cache | Centered error block: heading + body + "Try again" text button (44pt tall, accent text is NOT used here; use `text` color 16/600 with `backgroundElement` fill, radius 12, 16 horizontal padding) |
| Refresh failed, cache present | Keep the list. Show the refresh error line (Label, `destructive`) above the first row until the next successful fetch |
| Empty | Empty state block (copy below), centered, `cube.transparent` 48 icon in `textSecondary`, 16 gap, heading, 8 gap, body. Pull-to-refresh still works |
| Data | Rows |

Pull-to-refresh: `RefreshControl` with `tintColor={accent}`; refreshing shows only while a user-started refresh is in flight (background 5 s polling never shows the spinner).

Polling: every 5 s only while at least one item is uploading or processing (D-20). No visual indicator for polling.

Row action flow (D-21):
1. Tap "…" → `Alert.alert(title, undefined, [Rename, Delete (destructive), Cancel (cancel)])`. One code path on all platforms **[default]**.
2. Rename → Rename modal.
3. Delete → Delete confirmation → on confirm, the row disappears at once (optimistic). On API error the row comes back in its original position and the delete-failed alert shows.

### 4. Rename modal (D-21)

- RN `Modal`, `transparent`, `animationType="fade"`, `onRequestClose` = Cancel. Backdrop `rgba(0,0,0,0.4)`; tapping the backdrop = Cancel.
- Card: centered, width = screen width − 48 (max 400), `background` color, radius 16, padding 24, wrapped in `KeyboardAvoidingView` so the keyboard never covers it.
- Content: title (Heading 20/600) → 16 → `TextInput` (same input style as sign-in, prefilled with the current title, `autoFocus`, `selectTextOnFocus`, `maxLength={80}`, `returnKeyType="done"` which saves, `autoCapitalize="sentences"`) → 8 → helper / error line (Label) → 24 → button row right-aligned: "Cancel" (`text` 16/400) and "Save Name" (`accent` 16/600), each min 44 x 44, 16 apart.
- Save Name disabled (opacity 0.4) when the trimmed value is empty or equals the current title.
- Saving: "Save Name" is replaced by a small `ActivityIndicator` (accent), input not editable. On success the modal closes and the row shows the new title. On error the modal stays open and the error line shows.
- Helper line when idle: "{n}/80" (Label, `textSecondary`), right-aligned **[default]**.

### 5. Settings tab (D-09)

Layout: `ScrollView`, side padding 16, title "Settings" (Display) with 16 top / 24 bottom.
- Section heading "Account" (Heading 20/600) → 8 → card (`backgroundElement`, radius 12):
  - Row 1 (min 44, padding 16): label "Signed in as" (Label, `textSecondary`), below it the email (Body 16/400, selectable).
  - Hairline separator (`backgroundSelected`).
  - Row 2: "Log out" button, full card width, min height 52, centered text, `destructive` 16/600. Pressed: `backgroundSelected` fill.
- 24 gap, then the footer line (Label, `textSecondary`), centered: "Virtumetry {version} · {appEnv}" using `expo-constants` `expoConfig.version` and `EXPO_PUBLIC_APP_ENV` (so the owner can see which backend the build targets; supports success criterion 5) **[default]**.
- Log out → confirmation → on confirm: `authClient.signOut()`, clear the query cache, go to sign-in. If sign-out fails on the network, still clear the local session and go to sign-in (never trap the user signed in) **[default]**.

### 6. Tabs

`NativeTabs` with two triggers: `index` label "Library", `settings` label "Settings". Icons per the icon table. Selected tint = `accent`. `app-tabs.web.tsx` gets the same two tabs (labels "Library" / "Settings") so web keeps compiling.

## Copywriting Contract

Voice: short, plain, second person, no exclamation marks, no jargon ("world", "splat", "provider" never shown; the user sees "scan"). Ellipsis uses the single character "…".

| Password label / placeholder | Password / Your password |

| Settings title | Settings |
| Tab labels | Library · Settings |

### Sign-in errors (inline, `destructive`, Label)

| Condition | Copy |
|-----------|------|
| Wrong email/password, or email not allowlisted (same message, no account-existence leak, D-03) | That email and password don't match. Try again. |
| Rate limited (HTTP 429) | Too many attempts. Wait a minute, then try again. |
| Network failure / timeout | Can't reach Virtumetry. Check your connection and try again. |
| Server error (5xx) or anything else | Something went wrong on our side. Try again in a moment. |
| Session ended notice (after a 401, shown above the form in `textSecondary`) | You were logged out. Log in again to continue. |

### Library row status lines (D-19)

| Display state | Status line | Secondary line |
|---------------|-------------|----------------|
| saved_on_phone | Saved on phone · Not uploaded | {date} |
| uploading, progress known | Uploading · {n}% | none |
| uploading, progress unknown | Uploading… | none |
| packing | Processing · Preparing upload | estimate |
| submitting | Processing · Sending for processing | estimate |
| processing | Processing · Building your 3D room | estimate |
| importing | Processing · Finishing up | estimate |
| ready | Ready | {date} |
| failed | Failed · {human message} | {charge note} · {date} |
| cancelled | Cancelled | {date} |

Estimate (secondary line, `textSecondary`) for processing states:
- Progress known and the computed minutes ≥ 1: "About {n} min left" (n rounded up to the nearest whole minute)
- Computed minutes < 1: "Almost done"
- Progress unknown: "Usually 30 min – 2 h"

Stalled hint (replaces the estimate, `warning`, when `updated_at` is older than 15 min on any uploading or processing state): "Stalled? No update for {n} min. Pull down to refresh." For n ≥ 60 use "{h} h" instead of "{n} min" (e.g. "No update for 2 h").

Failed human messages (from `failure_code`; fallback used when the code is unknown, and `failure_message` is never shown raw) **[default]**:

| failure_code family | Human message |
|---------------------|---------------|
| upload / bundle stage failures | Upload didn't finish |
| provider rejected input (bad capture, too few frames) | The scan couldn't be turned into a room |
| provider timeout | Processing took too long |
| budget / limit refusal | Stopped by your spending limit |
| unknown / other | Something went wrong while processing |

Charge note: "Not charged" / "Charged for this run" / "Charge unknown" (when the API does not say). The planner maps exact codes in the display-state function and unit-tests the fallback.

| Interaction | Behavior |
|-------------|----------|
