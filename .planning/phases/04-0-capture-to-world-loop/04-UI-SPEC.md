# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mode: fully autonomous. No user questions were asked. **This spec extends 03-UI-SPEC.md and does not redefine it.** Tokens, type scale, colors, voice, row anatomy, button/input styles and accessibility rules from 03-UI-SPEC.md apply unchanged unless this file says otherwise. Every choice not locked in 04-CONTEXT.md is a researcher default, marked **[default]**.

## Scope

| Screen / surface | Route / mechanism | Source |
|------------------|-------------------|--------|
| Library "New scan" entry (header + empty state) | `src/app/(tabs)/index.tsx` | D-11 |
| Library rows for local scans (saved_on_phone, uploading, failed at checks) | `src/components/library-row.tsx`, `src/library/display-state.ts` | D-13, D-17 |
| Prep checklist + camera permission priming (full / compact / denied) | `src/app/capture/prep.tsx` | D-11, D-12 |
| Scan screen (preview, readiness, cost, coverage mini-map, fixture scenario control, Start / Stop / Cancel) | `src/app/capture/scan.tsx` | D-05, D-07, D-09, D-10 |
| Scan cancel confirmation | `Alert.alert` | D-14 **[default]** |
| Review → Quote → Upload (one screen, three steps) | `src/app/capture/[id].tsx` | D-14, D-15, D-17, D-18, D-21 |
| Discard confirmation | `Alert.alert` | D-14 |

`src/app/capture/` is a Stack outside the tabs, presented `fullScreenModal`, no native header (each screen draws its own top bar) (D-12). Review and quote are **one route with three steps** (Claude's discretion, D-14/D-18): `review` → `quote` → `upload`. Fewer files, and the "Approve & process" tap is still a separate explicit step.

Out of scope: real camera preview / ARKit (Phase 8), coaching prompts, tracking-loss pause, heat/storage warnings (Phase 8), viewer (Phase 5), retry (Phase 6), threshold tuning UI (deferred).

## Screen Contracts

**Focal points [default]:** Library — unchanged, plus the "New scan" pill top-right. Prep — the checklist, then the primary button. Scan — the readiness pill (what to do next); cost and mini-map are secondary. Review — the readiness/checks card, then "Upload". Quote — the credit line, then "Approve & process". Upload — progress bar and percent.

### 1. Library "New scan" entry (D-11)

- List header row: "Library" title (Display) left, "New scan" pill right, vertically centered on the title, same 16 top / 24 bottom as Phase 3. Pill: accent fill, `plus` 16 + "New scan" 16/600 `onAccent`, height 44, radius 22. Pressed opacity 0.8.
- Empty state: Phase 3 block (icon, heading, body) + 24 gap + "New scan" button: accent fill, height 52, radius 12, 16 horizontal padding, intrinsic width (not full width), centered.
- Both go to `capture/prep`, or straight to `capture/scan` when "Don't show again" is set AND camera permission is granted (or the fixture source is active and permission was already asked once).
- While a capture is in progress there is no second entry (the capture stack is a full-screen modal).

### 2. Library rows for local scans (D-13, D-17)

Row anatomy unchanged. Changes:
- Local rows (saved_on_phone, local upload in progress, local blocked-by-checks) are **pressable** and open `capture/[id]` at the matching step (saved_on_phone → `review`; approved/uploading/blocked → `upload`). Pressed: `backgroundSelected` fill. Server-only rows stay non-pressable (no detail screen until Phase 5).
- "…" menu on local rows: "Discard" (destructive) · Cancel → Discard confirmation. Local rows have no Rename (unchanged from Phase 3 code).
- Once the server reports the scan, the server row replaces the local row (same id mapping); the phone copy is deleted only at `packing` or later (D-14).

### 3. Prep checklist + camera priming (D-11)

Layout (system theme, `SafeAreaView`, `ScrollView`, side padding 16):
1. Top bar 44: "Cancel" text button left (16/400 `text`, closes the modal back to Library).
2. 16 gap, title "Before you scan" (Display).
3. 24 gap, checklist: 4 rows, each `[icon 24] 16 [title 16/600 / 8 / description 14/400 textSecondary]`, 16 between rows.
4. 24 gap, camera priming card (`backgroundElement`, radius 12, padding 16): `camera` icon 24 + 8 + heading (20/600) on one line, 8 gap, body (16/400).
5. 32 gap, primary button "Continue" (full width, 52, accent).

Behavior of "Continue":
- Permission `granted` → go to `capture/scan` (replace, so Back from scan does not land on prep).
- Permission `undetermined` (or `canAskAgain`) → `requestPermission()` (system prompt) → granted → scan; denied → denied state.
- Permission denied and `canAskAgain === false` → denied state shown directly on open.
- Button shows `ActivityIndicator` (`onAccent`) while the system prompt is pending; not pressable.

Variants:
- **First run** (no prep-seen flag): full layout above. Mark seen after the user taps Continue.
- **Compact** (seen before): checklist collapses to one Label line under the title: "Lights on · Doors open · No mirrors · Walk slowly". Priming card is replaced by a row with RN `Switch` + "Don't show again" (16/400), min height 44. Flag persisted with `expo-secure-store` (already installed) **[default]**.
- **Denied state**: replaces checklist and card. Centered block: `video.slash` 48 `textSecondary`, 16 gap, heading, 8 gap, body, 24 gap, primary "Open Settings" (`Linking.openSettings()`), 16 gap, text button "Not now" (16/400 `text`, closes to Library). When the fixture source is active, an extra text button "Use test capture" (16/600 `text`) appears between them, so the $0 loop stays testable **[default]**. When the app returns to `active`, re-read permission; if granted, show the normal Continue.

### 4. Scan screen (D-05, D-07, D-09, D-10)

Always dark. `expo-keep-awake` keeps the screen on while recording **[default]**, if it is installable without a native build (it ships in Expo Go); otherwise skip.

Layout, full screen:

```
┌ safe area ─────────────────────────────────────┐
│ [Cancel]          0:42           [Test capture]│  top bar 44, scrim
│ [ Good | Too few | Gap | Jump ]  (fixture only)│  16 below top bar
│                                    ┌─────────┐ │
│          PREVIEW (fills screen)    │ mini-map│ │  16 from right, 16 below control
│                                    │ 128x128 │ │
│                                    └─────────┘ │
│ ┌ HUD panel (scrim, radius 16, padding 16) ──┐ │
│ │ (●) Keep scanning                          │ │  readiness pill
│ │ Keep going — 12 more frames                │ │  4 below, reason 14/400
│ │ 16                                         │ │
│ │ $9.30 · 930 credits            30 frames   │ │  cost left, frames right
│ │ 24                                         │ │
│ │                ( STOP 72 )                 │ │
│ └────────────────────────────────────────────┘ │
└────────────────────────────────────────────────┘
```

- **Preview**: fixture source shows the most recently written frame with `expo-image` (`contentFit="cover"`, no transition) **[default]**; before the first frame it shows `backgroundElement` with "Test capture ready" (14/400 `textSecondary`) centered. The native source (Phase 8) puts its camera view in the same slot. Preview is decorative (`accessible={false}`).
- **Top bar**: "Cancel" (16/400 `text`, 44 target) left; elapsed timer "m:ss" (16/600, tabular) center, shown only while recording; "Test capture" chip right (14/400 `textSecondary`, `backgroundElement` fill, radius 12, padding 4/8) only with the fixture source.
- **Fixture scenario segmented control** (D-05): only when the fixture source is active. 4 equal segments: "Good" · "Too few" · "Gap" · "Jump" (Label 14). Track `backgroundElement`, selected segment `backgroundSelected`. Labels 14/400: selected `text`, unselected `textSecondary`. Default `Good`. Disabled (opacity 0.4) while recording. Built from `Pressable`s, no dependency.
- **Readiness pill** (D-07): scrim-free inside the panel, `backgroundElement` fill, icon 20 + 4 + label 16/600 in the level color. Under it, the single reason (14/400 `text`). Level is never shown by color alone: icon shape + label word + reason text.

  | Level | Icon | Label | Color |
  |-------|------|-------|-------|
  | green | `checkmark.circle.fill` | Good to finish | `accent` |
  | amber | `exclamationmark.circle.fill` | Almost there | `warning` |
  | red | `xmark.circle.fill` | Keep scanning | `destructive` |
  | idle (not started) | none | Ready to scan | `text` |

- **Cost meter** (D-09): "$9.30" Heading 20/600 `text` + " · 930 credits" Label 14/400 `textSecondary`, baseline-aligned, updated per keyframe. Before the first frame it shows the base cost "$9.00 · 900 credits". Right side: "{n} frames" 14/400 `textSecondary`.
- **Coverage mini-map** (D-10, `react-native-svg`): 128 x 128, scrim background, radius 12. Inside, with 8 inset:
  - Sector ring: 12 arcs of 30°, radius 52, stroke width 6, 2° gap between arcs. Seen = `accent` (dark), unseen = `rgba(255,255,255,0.2)`. 0° = the first frame's look direction pointing up.
  - Path: polyline of top-down camera centres (x/z), stroke 2, `text`, auto-fit inside a 72 x 72 inner box, keeping aspect ratio, minimum span 1 m so a standing-still start does not zoom to noise.
  - Heading ticks: every 5th keyframe, 6px line in look direction, `textSecondary`.
  - Current position: 4px radius dot `accent` + 10px heading tick `accent`.
  - Before the first frame: ring only, all unseen.
- **Start / Stop button**: 72 circle, centered in the panel.
  - Idle: accent fill, label "Start scan" 14/400 `text` below it (8 gap). Tap → `start()`.
  - Recording: 4px `text` ring, transparent fill, 28 x 28 `text` rounded square inside, label "Stop" below. Tap → `stop()` → navigate (replace) to `capture/[id]` step `review`. If 0 frames were captured, Stop behaves like Cancel without a confirmation.
  - Starting / stopping: inner icon replaced by `ActivityIndicator` (`text`), not pressable.
- **Cancel**: idle or 0 frames → close to Library at once. Recording with ≥ 1 frame → scan-cancel confirmation (see Destructive actions); "Delete scan" → `cancel()`, delete the session dir, close.
- Config: thresholds come from `GET /v1/capture/config` (react-query) with bundled fallback (D-08). No UI for the fetch state; offline silently uses defaults **[default]**.

### 5. Capture screen `capture/[id]` — step `review` (D-14, D-15)

System theme. `ScrollView`, side padding 16, bottom action area pinned above the safe area (`background` fill, 16 padding, hairline top separator).

1. Top bar 44: "Library" text button left (16/400, closes the modal; scan stays saved on phone).
2. 16 gap, title "Review scan" (Display), 8 gap, "Saved on phone" line with `iphone` 14 icon (Label `textSecondary`).
3. 24 gap, thumbnail strip: up to 5 frames evenly sampled (first, …, last), 64 x 64, radius 8, gap 8, horizontal `ScrollView` if it does not fit. Decorative.
4. 24 gap, stats card (`backgroundElement`, radius 12, padding 16), three rows, label left (14/400 `textSecondary`) / value right (16/600 tabular), 8 between rows:
   - Frames — "30"
   - Duration — "1:12" (m:ss)
   - Estimated cost — "$9.30 · 930 credits"
5. 24 gap, checks card: readiness pill (same as scan screen, using system theme colors) + 8 + reason, then hairline + 16, then precheck result:
   - Pass: `checkmark.circle.fill` accent + "Checks passed" (16/600).
   - Fail: heading "Didn't pass checks" (16/600 `destructive`) + 8 + one row per failed rule: `xmark.circle.fill` 20 `destructive` + 8 + reason (14/400 `text`).
6. Action area: primary "Upload" (full width, 52, accent). Disabled (opacity 0.4, `accessibilityState.disabled`) when precheck fails; the reason list above explains why. Below it, 16 gap, "Discard" text button (16/600 `destructive`, 44 tall, centered) → Discard confirmation → delete session dir + index entry → Library.
7. "Upload" → step `quote` (in place, no navigation).

Amber or red readiness with a passing precheck still allows Upload (readiness advises, precheck blocks) **[default]**.

### 6. Step `quote` (D-18, D-19)

Same screen, title "Approve processing" (Display).
- Loading: quote card shows `ActivityIndicator` (accent) + "Getting quote…" (14/400 `textSecondary`). "Approve & process" disabled.
- Loaded card (`backgroundElement`, padding 16): line 1 "This scan will use ~930 credits ≈ $9.30" with "~930 credits" in Heading 20/600 and the rest in Body 16/400 (one `Text` with nested styles); 8 gap; budget line (14/400 `textSecondary`): "{n} credits left in your budget" (uses the server's `budgetRemaining`; if it returns daily and monthly, show the smaller one and name it: "left today" / "left this month") **[default]**.
- Within budget is shown only after the server confirms (`withinBudget === true`), never computed locally.
- Over budget (`withinBudget === false`): `exclamationmark.triangle.fill` 20 `warning` + 8 + reason line (14/400 `warning`), "Approve & process" disabled.
- Error: card shows error copy (14/400 `destructive`) + "Try again" button (Phase 3 style: `text` 16/600 on `backgroundSelected`, radius 12, 44 tall).
- Note under the card (14/400 `textSecondary`): "Nothing is charged until you approve. If the scan fails checks, you're not charged."
- Action area: primary "Approve & process" (accent, 52). Secondary text button "Back" (16/400 `text`) → step `review`. Tapping Approve: button shows `ActivityIndicator`, creates the server scan with `approved_max_credits` (D-19), marks the local scan approved, hands it to the upload manager, then → step `upload`. No processing ever starts without this tap.

### 7. Step `upload` (D-17, D-21)

Same screen, title "Uploading" (Display).
- Progress block: status line "Uploading · {n}%" (16/600 tabular), 4 gap, progress bar (accent fill, full width), 8 gap, "{uploaded} of {total} files" (14/400 `textSecondary`). Unknown progress (before first reconcile): "Uploading…" and an indeterminate state (bar track only, no fill).
- Note (14/400 `textSecondary`): "You can close this screen. The upload picks up where it left off when you open the app again."
- Waiting for network (upload manager reports offline / repeated network errors): status line "Upload paused · Waiting for connection" (`textSecondary`), bar keeps last value.
- Done (`:complete` accepted, server at `packing`+): status line "Uploaded · Processing started", note "You'll see progress in your library." Action: "Back to Library" (neutral: `text` 16/600 on `backgroundSelected`, full width, 52, radius 12; not accent) **[default]**.
- **Blocked by checks** (server `failed`, `failure_stage=validate`): replaces the progress block. Centered: `xmark.circle.fill` 48 `destructive`, 16 gap, heading "Didn't pass checks" (20/600), 8 gap, the mapped reason (16/400), 8 gap, "Not charged" (14/400 `textSecondary`). Action: "Back to Library" (same neutral style). The local copy stays on the phone until discarded (no packing happened).
- Other failure (upload stale etc.): Phase 3 failed copy for that code, same layout.
- Action area while uploading: neutral "Back to Library" button (upload continues in the app-scoped manager).

### Readiness (one reason at a time, D-07)

Reason priority (first failing signal wins): tracking gap → blur → frame count → coverage.

| Level / signal | Label | Reason |
|----------------|-------|--------|
| idle | Ready to scan | Tap Start, then walk slowly around the room |
| red/amber · tracking gap | Keep scanning / Almost there | Tracking dropped — move slower and keep the lights on |
| red/amber · blur | Keep scanning / Almost there | Slow down — too many blurry photos |
| red/amber · frames | Keep scanning / Almost there | Keep going — {n} more frames |
| red/amber · coverage | Keep scanning / Almost there | Look around the rest of the room |
| green | Good to finish | You can stop now |

### Check reasons (review, upload, D-15/D-16)

Device rules (review step) and the same rules re-run on the server (upload step, mapped from `failure_code`):

| Rule | Reason copy |
|------|-------------|
| Too few frames | Too few photos ({n} of {min} needed). Scan again and keep walking. |
| Too many frames | Too many photos ({n}, limit {max}). Scan a smaller area. |
| Blur share | Too many blurry photos. Scan again, moving slower with the lights on. |
| Tracking-gap share | The phone lost track of where it was. Scan again with more light. |
| Coverage | Not enough of the room was seen ({n} of {min} directions). Look all the way around. |
| Pose jump (server) | The camera position jumped during the scan. Scan again, moving slowly. |
| Forward vs motion (server) | The camera seemed to face away from where you walked. Scan again, walking forward. |
| Intrinsics vs image (server) | The camera data looks wrong. Scan again. |
| Unknown validate code (fallback) | This scan didn't pass checks. Scan again. |

Server reasons are mapped from `failure_code` in a client table; `failure_message` is never shown raw (Phase 3 rule kept).

### Library row status lines (additions to Phase 3)

| State | Status line | Secondary line |
|-------|-------------|----------------|
| saved_on_phone | Saved on phone · Not uploaded (unchanged) | {n} frames · {date} |
| saved_on_phone, precheck failed | Saved on phone · Didn't pass checks | {n} frames · {date} |
| local approved, upload not started | Uploading… | none |
| local uploading, offline | Upload paused · Waiting for connection | none |
| failed at `validate` stage | Failed · Didn't pass checks | Not charged · {date} |

`failure_stage === 'validate'` maps to "Didn't pass checks" ahead of the Phase 3 code families **[default]**.

### Destructive actions

| Action | Confirmation title | Message | Buttons |
|--------|--------------------|---------|---------|
| Cancel during scan (≥ 1 frame) | Cancel scan? | The {n} photos captured so far will be deleted. | Keep scanning (cancel) · Delete scan (destructive) |
| Discard (review, or row "…") | Discard this scan? | This deletes its {n} photos from your phone. You can't undo this. | Cancel · Discard (destructive) |
| Discard failed (file delete error) | Couldn't discard | Try again. If it keeps failing, restart the app. | Back to Review |

Not destructive (no confirmation): Stop (keeps everything), Back (quote → review), closing the review/upload screen (scan stays saved, upload continues).
