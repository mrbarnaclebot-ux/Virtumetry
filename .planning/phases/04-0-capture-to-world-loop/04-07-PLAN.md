## Phase Goal

**As a** the owner, **I want to** run a fixture scan in Expo Go from prep through review, checks, quote, approval and a resumable upload to a "Ready" room in my library, **so that** I can trust the whole capture loop at zero cost before real ARKit capture and paid processing.

<objective>
Vertical slice 7 (upload that survives a force-quit): an approved scan on the phone uploads itself in the background of the app's lifetime, and after a force-quit the next launch asks the server what is missing, re-sends only that, uploads the manifest last and completes the scan.

Output: api.ts scan calls, pure `reconcile.ts`, `uploader.ts` adapter, `manager.ts` singleton, root-layout start, tests.
</objective>

<interfaces>
Server contract (plan 02/03, verbatim):
- POST /v1/scans, header `Idempotency-Key: <sessionId>`, body `{ title?, frame_count, image_w, image_h, approved_max_credits }` → `{ world }` (201 new / 200 replay).
- POST /v1/scans/:id/uploads body `{ files: [{ path, bytes }] }` (≤200) → `{ uploads: [{ path, url, method: 'PUT', headers }] }`.
- GET /v1/scans/:id/uploads:missing → `{ world, missingFrames: string[], manifestPresent: boolean, uploadedFrames: number, totalFrames: number }`.
- POST /v1/scans/:id:complete → 200 `{ world, issues?: string[] }` | 409 upload_incomplete.
- GET /v1/quote?frames=N → `{ credits, usd, budgetRemaining, budgetWindow: 'daily'|'monthly', withinBudget }`.
`world` = serializeWorld: `{ id, status, failure_stage, failure_code, charged, progress, … }` (same fields as LibraryItem in display-state.ts).
App: `apiFetch<T>(path, init)` throws `ApiError(status)` on non-2xx (body not exposed), `UnauthorizedError` on 401; merges `init.headers`. Store (plan 05): `getLocalScans`, `getLocalScan`, `updateLocalScan`, `discardLocalScan`-style dir delete; `LocalScan` / `LocalUploadState` ('saved'|'approved'|'uploading'|'paused'|'done'|'blocked'|'failed') in display-state.ts. Root layout `src/app/_layout.tsx`: session `data` from the auth client (line ~19), module-level AppState listener (lines 12-15).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → API | authenticated calls with the session cookie |
| app → R2 | presigned PUTs (no cookie) |
| API → app | missing/complete reports drive local deletion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-26 | Info disclosure | cookie leak to R2 | mitigate | R2 PUTs only via File.upload with the presigned headers; never apiFetch for presigned URLs |
| T-04-27 | Tampering | server-supplied path used for local file read | mitigate | uploader validates the path against the session-format allowlist before opening a file |
| T-04-28 | Data loss | premature local delete | mitigate | delete only when the server reports packing or later; blocked/failed keep files |
| T-04-29 | Tampering / cost | duplicate create on retry | mitigate | Idempotency-Key = sessionId on every create; server replays the same world |
| T-04-30 | Info disclosure | presigned URLs in logs | mitigate | log scan ids and counts only |
| T-04-31 | DoS | infinite retry loops | mitigate | one pass per trigger, in-flight guard, failures end the pass; next pass only on launch/foreground/kick |
</threat_model>
